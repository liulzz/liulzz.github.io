AgentScope Java 2.0 Agent 开发标准范式指南

来源：基于 agentscope-ai/agentscope-java 官方仓库（Oct 8, 2026 发布 2.0.4 / 2.1.0-BETA1）的 agentscope-examples 示例工程综合提炼。
定位：构建分布式、生产级、长时间运行 Agent 的企业级 Java 框架。
要求：JDK 17+ · Maven 3.6+ · Apache License 2.0 · 当前稳定版 2.0.4（2026-10-08） · 下一个发布 2.1.0

落地原则：示范代码全部按生产标准写——Spring Boot 容器管理 Bean 生命周期、WebFlux SSE 流式、Spring Security 鉴权、Micrometer 可观测、@PreDestroy 优雅停机，不出现 main()、不写 Demo。

第一性原理

ReActAgent（推理-行动循环内核，纯逻辑）
        ↓ 叠加
HarnessAgent（工程基础设施：工作区/记忆/技能/子Agent/压缩/恢复）
        ↓ 组装
你的业务代码（只写 Builder 配置 + @Tool 方法 + 可选 Middleware）

Java 版与 Python 版的最大差异：ReActAgent 与 HarnessAgent 分层。日常演示用 ReActAgent，生产长时间任务一律用 HarnessAgent。

🎯 范式 1：最简 Agent（ReActAgent 基线）

出处：examples/documentation2/quickstart/BasicChatExample.java

ReActAgent agent = ReActAgent.builder()
        .name("Assistant")
        .sysPrompt("You are a helpful AI assistant. Be friendly and concise.")
        .model("dashscope:qwen-plus")   // 字符串模型名，ModelRegistry 自动解析提供商与 API Key
        .toolkit(new Toolkit())          // 2.0 不再需要 .memory(...)，历史由 AgentState 持有
        .build();

// 流式输出（Reactor）
agent.streamEvents(new UserMessage("Hello!"))
        .doOnNext(event -> {
            if (event instanceof TextBlockDeltaEvent e) {
                System.out.print(e.getDelta());
            }
        })
        .blockLast();

// 或阻塞式
Msg reply = agent.call(new UserMessage("Hi")).block();

要点：
- model("dashscope:qwen-plus") 字符串即可，Registry 自动解析（也可显式 DashScopeChatModel.builder()...build()）
- 2.0 移除了 .memory(new InMemoryMemory()) —— 会话历史在 AgentState 里
- 事件流基于 Reactor（Flux/Mono），与 Spring WebFlux 天然契合

🔧 范式 2：工具调用（@Tool 注解）

出处：examples/documentation2/tool/ToolCallingExample.java

Toolkit toolkit = new Toolkit();
toolkit.registerTool(new SimpleTools());   // 一个类可含多个 @Tool 方法

ReActAgent agent = ReActAgent.builder()
        .name("ToolAgent")
        .sysPrompt("You are a helpful assistant with access to tools...")
        .model(DashScopeChatModel.builder()
                .apiKey(apiKey)
                .modelName("qwen-max")
                .stream(true)
                .enableThinking(false)
                .formatter(new DashScopeChatFormatter())
                .build())
        .toolkit(toolkit)
        .middleware(new AgentTraceMiddleware())   // 内置追踪中间件
        .build();

public static class SimpleTools {

    @Tool(name = "get_current_time",
          description = "Get the current time in a specific timezone")
    public String getCurrentTime(
            @ToolParam(name = "timezone",
                       description = "Timezone name, e.g., 'Asia/Tokyo'") String timezone) {
        // 纯 Java 方法，返回值即工具结果
        return "Current time in " + timezone + ": ...";
    }
}

工具规范：
- 一个 POJO 类，方法上加 @Tool(name, description)，参数上加 @ToolParam(name, description)
- 注册方式：toolkit.registerTool(instance)，Schema 从 Java 类自动生成
- 返回类型推荐 ToolResultBlock（显式 success()/error() 状态）；返回 String 也可
- 带进度的工具：方法追加 ToolEmitter emitter 参数，emitter.emit(...) 推进度（只给 UI 看，不进模型上下文）

🧩 范式 3：中间件六阶段（横切关注点）

出处：examples/documentation2/middleware/CustomizedMiddlewareExample.java

static class MonitoringMiddleware implements MiddlewareBase {

    @Override
    public Set<ExtensionPoint> activePoints() {
        return EnumSet.of(
            ExtensionPoint.ON_AGENT,       // 整个 agent 调用前后
            ExtensionPoint.ON_REASONING,   // 推理（模型调用）前后
            ExtensionPoint.ON_ACTING);     // 行动（工具执行）前后
    }

    @Override
    public Flux<AgentEvent> onAgent(Agent agent, RuntimeContext ctx,
                                    AgentInput input,
                                    Function<AgentInput, Flux<AgentEvent>> next) {
        System.out.println("[MW] onAgent START — session=" + ctx.sessionId()
                + " msgs=" + input.msgs().size());
        return next.apply(input)
                .doOnComplete(() -> System.out.println("[MW] onAgent END"));
    }

    @Override
    public Flux<AgentEvent> onActing(Agent agent, RuntimeContext ctx,
                                     ActingInput input,
                                     Function<ActingInput, Flux<AgentEvent>> next) {
        String tools = input.toolCalls().stream()
                .map(ToolUseBlock::getName).collect(Collectors.joining(", "));
        return next.apply(input)
                .doOnNext(e -> { if (e instanceof ToolProgressEvent p)
                    System.out.println("[MW] progress: " + p.getText()); });
    }
    // onReasoning / onModelCall / onSystemPrompt / onAgentStateReady 同理
}

六个扩展点（取代 v1 扁平钩子）：

扩展点 拦截时机 典型用途
onAgent 整轮调用前后 计时、审计、限流
onReasoning 模型推理前后 上下文裁剪、日志
onActing 工具执行前后 权限门控、进度监听
onModelCall 底层模型调用 重试、降级、计费
onSystemPrompt 系统提示组装 动态注入（RAG/记忆）
onAgentStateReady 状态就绪 恢复校验

💾 范式 4：会话持久化（AgentStateStore）

出处：examples/documentation2/state/StateExample.java

AgentStateStore stateStore =
        new JsonFileAgentStateStore(
                Paths.get(System.getProperty("user.home"),
                          ".agentscope", "examples", "sessions"));

ReActAgent agent = ReActAgent.builder()
        .name("Assistant")
        .sysPrompt("You are a helpful assistant with persistent memory...")
        .toolkit(new Toolkit())
        .stateStore(stateStore)              // 配置即自动加载/保存
        .defaultSessionId("alice_session")   // 同 sessionId 续聊
        .model(...)
        .build();

// 首次调用自动加载历史；每次交互后自动持久化
agent.call(new UserMessage("My name is Alice")).block();

// 读取历史
List<Msg> history = agent.getAgentState().getContext();

Store 可选实现：InMemory（测试）/ JsonFile（单机）/ MySQL / Redis / PostgreSQL（分布式）。
关键：2.0 不再有 agent.loadFrom()/saveTo() —— builder 上配 stateStore + sessionId 即全自动。

🏗️ 范式 5：HarnessAgent 生产范式（核心 · 2.0.4）

出处：官方 README Quick Start + 2.0.4 升级指南

// ① 启动时配置一次，线程安全共享
private static final HarnessAgent.Builder AGENT_BUILDER = HarnessAgent.builder()
        .name("assistant")
        .agentId("assistant")
        .sysPrompt("You are a helpful AI assistant.")
        .model("dashscope:qwen-plus")
        .workspace(Paths.get(".agentscope/workspace"));   // 工作区：文件/记忆/技能落地处

// ② 每次请求 build() + try-with-resources
try (HarnessAgent agent = AGENT_BUILDER.build()) {
    RuntimeContext ctx = RuntimeContext.builder()
            .sessionId("demo")      // 会话维度
            .userId("alice")        // 用户维度 —— 多租户隔离贯穿 workspace 路径/KV 命名空间/沙箱状态槽
            .build();

    // 阻塞式 —— 2.0.4：每次 call 返回 AgentRun 句柄，承载本次执行控制权
    AgentRun run = agent.call(new UserMessage("Hello!"), ctx).block();

    // 流式事件：32 种类型化事件
    agent.streamEvents(new UserMessage("Summarize today."), ctx)
            .doOnNext(event -> {
                switch (event.getType()) {
                    case TEXT_BLOCK_DELTA ->
                        System.out.print(((TextBlockDeltaEvent) event).getDelta());
                    case TOOL_CALL_START ->
                        System.out.println("[tool] "
                            + ((ToolCallStartEvent) event).getToolCallName());
                    default -> { }
                }
            })
            .blockLast();
}

2.0.4 新增：AgentRun + RunControl（每次调用一份）

try (HarnessAgent agent = AGENT_BUILDER.build()) {
    AgentRun run = agent.call(new UserMessage("..."), ctx).block();

    // 中途取消：只影响本次 run，不污染 agent
    run.cancel();

    // 查看本次执行的元数据
    run.getRunId();
    run.isCompleted();
}

2.0.4 新增：ToolRequestConfig（请求级工具隔离）

ToolRequestConfig toolCfg = ToolRequestConfig.builder()
        .visibleToolNames(Set.of("get_current_time", "calculate"))  // 本次只暴露这些
        .streamingCallbacks(myCallbacks)                            // 流式回调
        .sessionSkillResources(mySkillBundle)                       // 会话级技能资源
        .build();

agent.call(new UserMessage("..."), ctx, toolCfg).block();

2.0.4 关键变化：RuntimeContext 显式传递

// 旧（2.0.3）: 通过实现 RuntimeContextAware 让框架自动塞入
public class MyTool implements RuntimeContextAware {
    @Override public void setRuntimeContext(RuntimeContext rc) { ... }   // 2.0.4 已删除
}

// 新（2.0.4）: 工具方法直接声明 RuntimeContext 参数（不加 @ToolParam，模型看不见）
@Tool(name = "my_action", description = "...")
public String myAction(
        @ToolParam(name = "arg") String arg,
        RuntimeContext ctx) {                                            // ← 显式注入
    return "session=" + ctx.sessionId() + " processed " + arg;
}

中间件签名上 RuntimeContext 仍在 onAgent(Agent, RuntimeContext, ...) 第二个参数，无需变更。

📐 通用设计原则（从全部示例提炼）

  1. Builder 一次配置，多次 build() —— Builder 静态共享，请求级实例 try-with-resources
  2. 工具 = POJO + @Tool 注解 —— 不写调度代码，Schema 自动生成
  3. 横切关注点全走 Middleware 六阶段 —— 不侵入业务逻辑
  4. 配置即持久化 —— stateStore + sessionId 替代手动 load/save
  5. RuntimeContext 承载多租户 —— sessionId/userId 从入口一路贯穿到 workspace 与沙箱
  6. Reactor 流式优先 —— streamEvents + Flux，与 Spring WebFlux/SSE 无缝
  7. ReActAgent 起步，HarnessAgent 进生产 —— 长任务、多租户、恢复能力只在上层提供
  8. 事件系统是一等公民 —— 32 种类型化事件：模型调用、文本增量、工具执行、用户确认全覆盖；ToolProgressEvent 只给 UI，不污染模型上下文

7.5 多租户解析 RuntimeContextResolver.java

@Component
public class RuntimeContextResolver {

    /** 从 Header 拿租户身份；缺失则拒绝（由 Controller 抛 400） */
    public RuntimeContext resolve(@Nullable String userId,
                                  @Nullable String sessionId) {
        if (userId == null || userId.isBlank()) {
            throw new MissingTenantHeaderException("X-User-Id 不能为空");
        }
        if (sessionId == null || sessionId.isBlank()) {
            throw new MissingTenantHeaderException("X-Session-Id 不能为空");
        }
        return RuntimeContext.builder()
                .userId(userId)
                .sessionId(sessionId)
                .build();
    }
}

MissingTenantHeaderException 用 @RestControllerAdvice 统一映射成 400。

7.6 同步 REST ChatRestController.java

@Slf4j
@RestController
@RequestMapping("/api/v1/chat")
@RequiredArgsConstructor
@Validated
public class ChatRestController {

    private final HarnessAgent agent;
    private final RuntimeContextResolver ctxResolver;
    private final AgentProperties props;

    /** 同步：等全部跑完一次性返回（适合短任务，< 30s） */
    @PostMapping(produces = MediaType.APPLICATION_JSON_VALUE)
    public ResponseEntity<ChatResponse> chat(@Valid @RequestBody ChatRequest req,
                                             @RequestHeader("X-User-Id") String userId,
                                             @RequestHeader("X-Session-Id") String sessionId) {
        RuntimeContext ctx = ctxResolver.resolve(userId, sessionId);
        AgentInput input = new AgentInput(List.of(new UserMessage(req.message())));

        // 2.0.4 拿 AgentRun 句柄，配合 ToolRequestConfig
        AgentRun run = agent.call(input, ctx, ToolRequestConfig.defaults())
                            .timeout(props.getAgentTimeout())   // Reactor 超时
                            .block();

        return ResponseEntity.ok()
                .header("X-Trace-Id", run.traceId())
                .body(ChatResponse.from(run));
    }
}

注意：agent.call(...) 返回的是 Mono<AgentRun>，.block() 只在同步控制器用；流式 Controller 永远不 .block()。

7.7 流式 SSE ChatStreamController.java

@Slf4j
@RestController
@RequestMapping("/api/v1/chat")
@RequiredArgsConstructor
@Validated
public class ChatStreamController {

    private final HarnessAgent agent;
    private final RuntimeContextResolver ctxResolver;
    private final AgentProperties props;

    /**
     * SSE 流式：浏览器/移动端逐 token / 逐事件拿到结果
     *  - Content-Type: text/event-stream
     *  - 每条 event 形如：event: TEXT_BLOCK_DELTA\ndata: {"text":"..."}\n\n
     */
    @GetMapping(value = "/sse", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<StreamChunk>> stream(@RequestParam @NotBlank String message,
                                                      @RequestHeader("X-User-Id") String userId,
                                                      @RequestHeader("X-Session-Id") String sessionId) {
        RuntimeContext ctx = ctxResolver.resolve(userId, sessionId);
        AgentInput input = new AgentInput(List.of(new UserMessage(message)));

        return agent.streamEvents(input, ctx, ToolRequestConfig.defaults())
                .timeout(props.getAgentTimeout())
                .map(event -> ServerSentEvent.<StreamChunk>builder()
                        .id(event.id())
                        .event(event.getType().name())           // 32 种类型化事件
                        .data(StreamChunk.from(event))
                        .build())
                // 心跳：防止 nginx/ALB 60s 切断（默认 15s）
                .mergeWith(Flux.interval(props.getSse().getKeepAlive())
                        .map(tick -> ServerSentEvent.<StreamChunk>builder()
                                .event("PING").comment("keep-alive").build()))
                .onErrorResume(e -> {
                    log.error("SSE stream failed for user={} session={}", userId, sessionId, e);
                    return Flux.just(ServerSentEvent.<StreamChunk>builder()
                            .event("ERROR")
                            .data(StreamChunk.error(e.getClass().getSimpleName(), e.getMessage()))
                            .build());
                });
    }
}

背压说明：HarnessAgent 的 streamEvents() 已经是 Flux<AgentEvent>，与 WebFlux 同源，不要 .block() / .toFuture() / .collectList()——任何中间缓冲都会把流式变回同步。

7.10 横切中间件 AuthAuditMiddleware.java

@Component
@RequiredArgsConstructor
public class AuthAuditMiddleware extends MiddlewareBase {

    private final MeterRegistry meterRegistry;
    private final AuditLogRepository auditRepo;

    @Override
    public Mono<AgentEvent> onAgentCall(Agent agent, RuntimeContext ctx,
                                         AgentInput input,
                                         Function<AgentInput, Mono<AgentEvent>> next) {
        Timer.Sample sample = Timer.start(meterRegistry);
        return next.apply(input)
                .doOnSubscribe(s -> {
                    auditRepo.log(ctx, "AGENT_CALL", "user=" + ctx.userId() + " msg_len="
                            + input.firstMessage().text().length());
                })
                .doOnSuccess(e -> sample.stop(Timer.builder("agent.call.latency")
                        .tag("user", ctx.userId()).register(meterRegistry)))
                .doOnError(e -> {
                    meterRegistry.counter("agent.call.error",
                            "user", ctx.userId(),
                            "code", e.getClass().getSimpleName()).increment();
                });
    }
}

7.13 优雅停机 AgentLifecycle.java

@Slf4j
public class AgentLifecycle implements DisposableBean {

    private final HarnessAgent agent;
    private final RuntimeContextResolver resolver;
    private final AtomicInteger inFlight = new AtomicInteger();

    public int inFlightCount() { return inFlight.get(); }

    /** Controller 调用前后打点 */
    public void enter()  { inFlight.incrementAndGet(); }
    public void exit()   { inFlight.decrementAndGet(); }

    /**
     * Spring 关闭时（SIGTERM）触发：
     *  - 等 K8s readiness=false 摘流量
     *  - 通知 HarnessAgent 进入 draining 状态
     *  - 给在飞请求一个 graceful 窗口（配 application.yml 的 timeout-per-shutdown-phase）
     */
    @Override
    @PreDestroy
    public void destroy() {
        log.info("Agent lifecycle shutting down, in-flight={}", inFlight.get());
        // 1) 关闭新请求入口（由 Tomcat/WebFlux 自身处理）
        // 2) 等待 inFlight==0 或超时
        long deadline = System.nanoTime() + Duration.ofSeconds(25).toNanos();
        while (inFlight.get() > 0 && System.nanoTime() < deadline) {
            try { Thread.sleep(100); } catch (InterruptedException ie) { Thread.currentThread().interrupt(); break; }
        }
        // 3) 强制关闭 HarnessAgent 内部资源
        if (inFlight.get() > 0) {
            log.warn("Force-closing with {} requests still in flight", inFlight.get());
        }
        agent.close();    // 2.0.4 提供的 try-with-resources 风格的 close()
        log.info("Agent lifecycle closed");
    }
}

Controller 加个 Filter 调 lifecycle.enter() / lifecycle.exit()（try/finally）即可。

@RestControllerAdvice

    }

7.16 反模式清单（不要这么写）

反模式 为什么不行 正确做法
main() 里 new HarnessAgent() 没人管生命周期，无法优雅停机 用 @Bean 让 Spring 注入
agent.call(...).block() 放在流式 Controller 把流式退化成同步，吞掉背压 return agent.streamEvents(...)
静态字段 private static final AGENT_BUILDER 绕过容器，无法注入中间件/工具 写 @Configuration Bean
try-with-resources 每次请求开新 Agent 模型连接、工具缓存每次重建 单例 HarnessAgent + 每请求 AgentRun
不传 RuntimeContext 调 agent 所有用户共享同一个会话，泄漏数据 Header 解析 + 每次请求构造 ctx
@Tool 方法里直接 new 一个 service 拿不到事务、连接池 注入 @Service 业务 Bean
流式返回前 .collectList() 把所有事件攒到内存再发 保持 Flux<ServerSentEvent> 形态
关闭时不通知 HarnessAgent 在飞请求被强杀，用户看到断流 @PreDestroy + grace 期

🎓 一句话总结

Java 版范式的灵魂是"分层与配置化"：ReActAgent 管推理循环，HarnessAgent 叠工程能力，AgentSession 管长任务生命周期；工具用 @Tool 注解、横切用 Middleware 六阶段、多租户用 RuntimeContext 显式贯穿、持久化配 stateStore 即自动 —— 业务代码只写 Builder 和注解，其余交给框架。
2.0.4 起：每次调用拿到 AgentRun 句柄；工具可见性/回调/技能资源可按请求隔离（ToolRequestConfig）；RuntimeContext 不再依赖 RuntimeContextAware 自动注入，全部走显式声明。
