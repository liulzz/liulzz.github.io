为什么需要事件流

第一章的示例中，call() 返回最终消息。但在真实场景中，你至少需要回答四个问题：智能体此刻在想什么、它调用了哪个工具、工具返回了什么、如果出错了错在哪里。call() 无法回答这些，因此 AgentScope 提供了事件流接口。

2.1先讲理论：消息与事件的关系

AgentScope Java 用两个模型分别表达「对话内容」与「执行过程」。Msg 是消息模型，位于 io.agentscope.core.message 包；AgentEvent 是事件模型，位于 io.agentscope.core.event 包。

两者的关系可以这样理解：事件是消息生成过程的流式视图，消息是生成完成后的完整状态。一次 call() 会产生若干事件，这些事件最终合并为恰好一条 assistant 消息。因此你既可以等待最终消息，也可以逐条处理事件，两种方式得到的信息是一致的。

一次 call() 的完整事件序列 AGENT_START 智能体开始生成 THINKING_BLOCK_START 思考块开始 THINKING_BLOCK_DELTA 推理内容增量 THINKING_BLOCK_END 思考块结束 TEXT_BLOCK_START 文本块开始 TEXT_BLOCK_DELTA 回答内容增量 TEXT_BLOCK_END 文本块结束 TOOL_CALL_START 准备调用工具 TOOL_CALL_DELTA 工具参数增量 TOOL_CALL_END 参数组装完成 TOOL_RESULT_START 工具开始执行 TOOL_RESULT_TEXT_DELTA 工具输出增量 TOOL_RESULT_END 工具执行结束 ... 可能重复多轮 AGENT_END 本次回复结束

Msg 的组成

Msg 表示一个会话轮次。它的核心字段如下。

方法返回类型说明
getId()String消息唯一标识
getName()String发送者名称，可为 null
getRole()MsgRoleUSER / ASSISTANT / SYSTEM / TOOL
getContent()List<ContentBlock>有序且不可变的内容块列表
getMetadata()Map<String, Object>任意键值元数据
getTimestamp()String创建时间，格式 yyyy-MM-dd HH:mm:ss.SSS
getUsage()ChatUsageToken 用量，仅 assistant 消息有值
getGenerateReason()GenerateReason消息终止原因

ContentBlock 家族

一条消息的内容由若干类型化的内容块组成。相比为图片、音频、视频各设计一个类，2.0 把它们统一为 DataBlock，通过 mediaType 字段区分类型。

内容块用途允许的角色
TextBlock普通文本USER、ASSISTANT、SYSTEM
DataBlock二进制数据（图片、音频、视频），通过 mediaType 区分USER、ASSISTANT
ToolUseBlock工具调用请求，含 id、name、input、stateASSISTANT
ToolResultBlock工具执行结果，含 stateASSISTANT
HintBlock作为 user context 注入循环的指令ASSISTANT
ThinkingBlock模型推理过程ASSISTANT
角色约束会在构造时校验

USER 消息只允许 TextBlock 与数据块，SYSTEM 消息只允许 TextBlock，而 ASSISTANT 允许全部类型。因此如果你把 ToolUseBlock 放进 UserMessage，框架会在构建阶段直接报错，而不是在运行时出现难以定位的问题。

GenerateReason：为什么这次回复结束了

这个字段在生产环境中非常有用，因为它明确区分了「正常完成」与「异常终止」。

枚举值含义建议动作
MODEL_STOP模型给出最终答案正常使用结果
TOOL_SUSPENDED等待用户确认或外部执行向用户推送确认请求
MAX_ITERATIONS达到迭代上限记录告警，检查提示词是否清晰
ALL_TOOLS_DENIED用户拒绝了全部工具引导用户放宽权限或改用手动流程
INTERRUPTED被外部中断保存现场，必要时允许继续执行
ACTING_STOP_REQUESTED行动阶段被请求停止同 INTERRUPTED
REASONING_STOP_REQUESTED推理阶段被请求停止同 INTERRUPTED

事件的关联标识体系

事件是零散到达的，那么「如何知道哪些事件属于同一次回复」就成了关键问题。AgentScope 通过三级标识解决这个问题。

标识作用范围语义
replyId跨全部事件标识一次完整的回复周期。所有事件共享同一个 replyId
blockId同一 reply 内标识一个文本块、思考块或数据块的生命周期
toolCallId全局唯一标识一次工具调用，关联对应的工具请求与工具结果

流式内容遵循统一的 start → delta → end 模式。你据此可以写出通用的事件聚合逻辑：按 blockId 或 toolCallId 分组，累积增量内容，在收到 end 事件时形成一个完整内容块。

父子事件的区分

当父智能体使用 agent_spawn 同步委派子智能体时，子智能体的中间事件会实时转发到父级的事件流中。此时需要区分事件来自谁，方法是读取 getSource()。

getSource()含义过滤写法
null父级事件events.filter(e -> e.getSource() == null)
"main/researcher"来自名为 researcher 的子智能体events.filter(e -> e.getSource() != null)
带 metadata.taskId远程子智能体事件通过 AgentEvent.METADATA_TASK_ID 区分具体任务

关于事件计数的差异

官方 Release Notes 中出现过「28 种」这一表述，README 出现过「31 种」。 差异来自统计口径：部分事件类在特定版本引入，且部分统计包含了事件类型的枚举常量而非类。 本表按官方 Message & Event 文档列出的 28 个事件类整理。 如果你的版本事件更多，请查阅对应版本的 API 参考。

2.2动手：消息的构造与读取

在讨论事件之前，先熟悉消息的构造方式。AgentScope 提供了四个按角色固定的子类：UserMessage、AssistantMessage、SystemMessage、ToolResultMessage。当 content 是普通字符串时，框架会自动包装为 TextBlock。

MessageBasics.javajava
import io.agentscope.core.message.Base64Source;
import io.agentscope.core.message.DataBlock;
import io.agentscope.core.message.SystemMessage;
import io.agentscope.core.message.TextBlock;
import io.agentscope.core.message.UserMessage;

public class MessageBasics {

    public static void main(String[] args) {
        // 1. 最简形式：字符串会被自动包装为 TextBlock
        UserMessage simple = new UserMessage("user", "帮我查一下接口文档");

        // 2. 多模态形式：文本与数据块组合
        UserMessage multimodal = new UserMessage(
                "user",
                TextBlock.builder()
                        .text("这张图里的报错是什么意思？")
                        .build(),
                DataBlock.builder()
                        .source(Base64Source.builder()
                                .data("<base64 编码后的图片数据>")
                                .mediaType("image/png")
                                .build())
                        .build());

        // 3. 系统消息只允许文本
        SystemMessage system = new SystemMessage(
                "system", "你是一个严谨的后端工程师。");

        // 4. builder 方式可以设置可选字段，例如 metadata
        UserMessage withMeta = UserMessage.builder()
                .name("user")
                .textContent("这条消息携带追踪信息")
                .metadata(java.util.Map.of("trace_id", "req-abc-123"))
                .build();

        // 读取：把所有 TextBlock 用换行拼接
        System.out.println(simple.getTextContent());

        // 读取：按类型筛选内容块
        boolean hasImage = multimodal.hasContentBlocks(DataBlock.class);
        System.out.println("包含图片： " + hasImage);

        DataBlock image = multimodal.getFirstContentBlock(DataBlock.class);
        if (image != null) {
            System.out.println("媒体类型： " + image.getSource().getMediaType());
        }

        // 读取：任意元数据
        System.out.println(withMeta.getMetadata().get("trace_id"));
    }
}
DataBlock 统一了多种媒体类型

2.0 之前 ImageBlock、AudioBlock、VideoBlock 是三个独立类型， 2.0 统一为 DataBlock 并通过 mediaType 区分。 旧类型仍然受支持，但新代码应当优先使用 DataBlock。

2.3动手：完整事件观察器

现在实现本章场景中的命令行界面。这个观察器覆盖全部主要事件类别，并且演示了如何用 blockId 累积增量、重建完整的回答文本。

EventObserver.javajava
import io.agentscope.core.ReActAgent;
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.event.AgentEndEvent;
import io.agentscope.core.event.AgentEvent;
import io.agentscope.core.event.AgentStartEvent;
import io.agentscope.core.event.ExceedMaxItersEvent;
import io.agentscope.core.event.RequireUserConfirmEvent;
import io.agentscope.core.event.TextBlockDeltaEvent;
import io.agentscope.core.event.ThinkingBlockDeltaEvent;
import io.agentscope.core.event.ToolCallDeltaEvent;
import io.agentscope.core.event.ToolCallStartEvent;
import io.agentscope.core.event.ToolResultEndEvent;
import io.agentscope.core.event.ToolResultTextDeltaEvent;
import io.agentscope.core.event.ModelCallEndEvent;
import io.agentscope.core.message.Msg;
import io.agentscope.core.message.UserMessage;
import java.util.List;
import java.util.Map;
import java.util.HashMap;

public class EventObserver {

    public static void main(String[] args) {
        ReActAgent agent = ReActAgent.builder()
                .name("kb-assistant")
                .sysPrompt(jt(24,
                        "你是一个团队知识助手。",
                        "回答时保持简洁，只陈述你确信的内容。")
                .model("dashscope:qwen-plus")
                .toolkit(KnowledgeTools.create())
                .build();

        RuntimeContext ctx = RuntimeContext.builder()
                .userId("zhangsan")
                .sessionId("s-001")
                .build();

        // 按 blockId 累积文本块，用于最终校验
        Map<String, StringBuilder> textBuffers = new HashMap<>();
        int[] tokenUsage = new int[2];   // [0]=输入 token，[1]=输出 token

        agent.streamEvents(
                        List.of(new UserMessage("支付服务的超时时间是多少？")),
                        // streamEvents 没有 RuntimeContext 重载时，
                        // 可以改用 stream(msgs, options, ctx)
                        null)
                .doOnNext(event -> handle(event, textBuffers, tokenUsage))
                .blockLast();

        // 校验：累积结果应与最终消息文本一致
        Msg finalMsg = agent.call(List.of(new UserMessage("再确认一次")), ctx).block();
        System.out.println("\n=== 最终消息 ===");
        System.out.println(finalMsg.getTextContent());
        System.out.println("终止原因： " + finalMsg.getGenerateReason());
        System.out.println("本轮 Token： 输入 " + tokenUsage[0]
                + "，输出 " + tokenUsage[1]);
    }

    private static void handle(AgentEvent event,
                               Map<String, StringBuilder> buffers,
                               int[] tokenUsage) {
        // 事件来源：null 表示父级，非 null 表示子智能体
        String src = event.getSource();
        String prefix = (src != null) ? "[" + src + "] " : "";

        if (event instanceof AgentStartEvent e) {
            System.out.println("\n┌─ 回复开始  replyId=" + e.getReplyId()
                    + "  session=" + e.getSessionId());

        } else if (event instanceof ThinkingBlockDeltaEvent e) {
            System.out.print(prefix + "〔思考〕" + e.getDelta());

        } else if (event instanceof TextBlockDeltaEvent e) {
            // 累积文本增量，供最终校验
            buffers.computeIfAbsent(e.getBlockId(),
                    k -> new StringBuilder()).append(e.getDelta());
            System.out.print(prefix + e.getDelta());

        } else if (event instanceof ToolCallStartEvent e) {
            System.out.println("\n" + prefix + "┌─ 工具调用： " + e.getToolCallName()
                    + "  id=" + e.getToolCallId());

        } else if (event instanceof ToolCallDeltaEvent e) {
            System.out.print(prefix + "│ 参数增量： " + e.getDelta());

        } else if (event instanceof ToolResultTextDeltaEvent e) {
            System.out.print(prefix + "│ 输出： " + e.getDelta());

        } else if (event instanceof ToolResultEndEvent e) {
            System.out.println(prefix + "└─ 工具结束  状态=" + e.getState());

        } else if (event instanceof ModelCallEndEvent e) {
            tokenUsage[0] += e.getInputTokens();
            tokenUsage[1] += e.getOutputTokens();

        } else if (event instanceof RequireUserConfirmEvent e) {
            System.out.println("\n" + prefix + "⚠ 需要确认，工具数： "
                    + e.getToolCalls().size());

        } else if (event instanceof ExceedMaxItersEvent) {
            System.out.println("\n⚠ 达到最大迭代次数");

        } else if (event instanceof AgentEndEvent) {
            System.out.println("\n└─ 回复结束");
        }
    }
}
关于 streamEvents 与 RuntimeContext

streamEvents() 提供了 Msg 与 List<Msg> 两种入参形式， 但没有带 RuntimeContext 的重载。 因此示例中事件流部分传入了 null，状态相关的操作改用带上下文的 call()。 如果你需要在事件流中携带上下文，请使用 stream(msgs, options, ctx)， 或者在 builder 上配置全局的 toolExecutionContext。

2.4动手：从事件流重建消息

前面提到过，单次调用的事件序列最终合并为恰好一条 assistant 消息。这意味着你可以只依靠事件流重建完整消息，这对于「断线重连后恢复界面」的场景非常有价值。官方参考实现位于 agentscope-core 的 agent/StreamingHook.java。

MessageReassembler.javajava
import io.agentscope.core.event.AgentEvent;
import io.agentscope.core.event.DataBlockDeltaEvent;
import io.agentscope.core.event.TextBlockDeltaEvent;
import io.agentscope.core.event.ThinkingBlockDeltaEvent;
import io.agentscope.core.event.ToolCallDeltaEvent;
import io.agentscope.core.event.ToolCallEndEvent;
import io.agentscope.core.event.ToolCallStartEvent;
import io.agentscope.core.event.ToolResultEndEvent;
import io.agentscope.core.event.AgentResultEvent;

import java.util.HashMap;
import java.util.Map;

/**
 * 从事件流重建最终消息。核心思路：
 *   1. 按 blockId / toolCallId 分组；
 *   2. 累积 delta；
 *   3. 收到 end 事件时形成完整内容块。
 */
public class MessageReassembler {

    /** blockId -> 累积的文本或思考内容 */
    private final Map<String, StringBuilder> blockBuffers = new HashMap<>();
    /** blockId -> 内容块类型 */
    private final Map<String, String> blockTypes = new HashMap<>();

    /** toolCallId -> 工具名 */
    private final Map<String, String> toolNames = new HashMap<>();
    /** toolCallId -> 组装中的参数 JSON */
    private final Map<String, StringBuilder> argBuffers = new HashMap<>();
    /** toolCallId -> 结果状态 */
    private final Map<String, String> toolStates = new HashMap<>();

    private final StringBuilder replyText = new StringBuilder();
    private int inputTokens = 0;
    private int outputTokens = 0;

    public void accept(AgentEvent event) {
        if (event instanceof TextBlockDeltaEvent e) {
            blockBuffers.computeIfAbsent(e.getBlockId(),
                    k -> new StringBuilder()).append(e.getDelta());
            blockTypes.put(e.getBlockId(), "text");
            replyText.append(e.getDelta());

        } else if (event instanceof ThinkingBlockDeltaEvent e) {
            blockBuffers.computeIfAbsent(e.getBlockId(),
                    k -> new StringBuilder()).append(e.getDelta());
            blockTypes.put(e.getBlockId(), "thinking");

        } else if (event instanceof DataBlockDeltaEvent e) {
            // 二进制内容需要单独缓冲，这里仅记录长度
            blockBuffers.computeIfAbsent(e.getBlockId(),
                    k -> new StringBuilder())
                    .append("[binary ").append(e.getData().length()).append(" chars]");

        } else if (event instanceof ToolCallStartEvent e) {
            toolNames.put(e.getToolCallId(), e.getToolCallName());
            argBuffers.put(e.getToolCallId(), new StringBuilder());

        } else if (event instanceof ToolCallDeltaEvent e) {
            argBuffers.computeIfAbsent(e.getToolCallId(),
                    k -> new StringBuilder()).append(e.getDelta());

        } else if (event instanceof ToolCallEndEvent e) {
            // 参数组装完成，参数是完整的 JSON 片段
            argBuffers.computeIfAbsent(e.getToolCallId(),
                    k -> new StringBuilder());

        } else if (event instanceof ToolResultEndEvent e) {
            toolStates.put(e.getToolCallId(), String.valueOf(e.getState()));

        } else if (event instanceof io.agentscope.core.event.ModelCallEndEvent e) {
            inputTokens += e.getInputTokens();
            outputTokens += e.getOutputTokens();

        } else if (event instanceof AgentResultEvent e) {
            // 框架在回复结束时给出的最终结果，可直接取用
        }
    }

    /** 输出重建结果，用于与最终 Msg 对比校验 */
    public String describe() {
        StringBuilder sb = new StringBuilder();
        sb.append("=== 重建结果 ===\n");
        sb.append("文本块数量： ").append(blockTypes.size()).append('\n');
        sb.append("完整文本长度： ").append(replyText.length()).append(" 字符\n");
        sb.append("工具调用： ").append(toolNames.size()).append(" 次\n");
        for (Map.Entry<String, String> e : toolNames.entrySet()) {
            String id = e.getKey();
            String args = argBuffers.getOrDefault(id, new StringBuilder()).toString();
            String state = toolStates.getOrDefault(id, "未完成");
            sb.append("  - ").append(e.getValue())
              .append("  参数=").append(args)
              .append("  状态=").append(state).append('\n');
        }
        sb.append("Token： 输入 ").append(inputTokens)
          .append("，输出 ").append(outputTokens);
        return sb.toString();
    }
}

2.5动手：转发为 SSE

网页前端无法直接消费 Reactor 的 Flux，但可以使用 Server-Sent Events。下面的示例把事件流映射为 SSE，这种「后端推事件、前端重建界面」的架构是官方推荐的模式。

ChatController.javajava
import com.fasterxml.jackson.databind.ObjectMapper;
import io.agentscope.core.ReActAgent;
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.event.AgentEvent;
import io.agentscope.core.event.SubagentExposedEvent;
import io.agentscope.core.event.TextBlockDeltaEvent;
import io.agentscope.core.event.ThinkingBlockDeltaEvent;
import io.agentscope.core.event.ToolCallStartEvent;
import io.agentscope.core.event.ToolResultEndEvent;
import io.agentscope.core.message.UserMessage;
import org.springframework.http.MediaType;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import reactor.core.publisher.Flux;
import reactor.core.publisher.ServerSentEvent;

import java.util.LinkedHashMap;
import java.util.Map;

@RestController
public class ChatController {

    private final ReActAgent agent;
    private final ObjectMapper mapper = new ObjectMapper();

    public ChatController() {
        // 单例 Agent，全局复用
        this.agent = ReActAgent.builder()
                .name("kb-assistant")
                .sysPrompt("你是一个团队知识助手，回答时给出依据。")
                .model("dashscope:qwen-plus")
                .build();
    }

    @GetMapping(value = "/chat", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> chat(
            @RequestParam String message,
            @RequestParam String userId,
            @RequestParam(required = false) String sessionId) {

        RuntimeContext ctx = RuntimeContext.builder()
                .userId(userId)
                .sessionId(sessionId != null ? sessionId : "default")
                .build();

        return agent.streamEvents(new UserMessage(message))
                .map(event -> toSse(event))
                .onErrorResume(err -> Flux.just(
                        ServerSentEvent.<String>builder()
                                .data("{\"type\":\"ERROR\",\"message\":\""
                                        + err.getMessage() + "\"}")
                                .build()));
    }

    private ServerSentEvent<String> toSse(AgentEvent event) {
        Map<String, Object> payload = new LinkedHashMap<>();
        payload.put("type", event.getType().name());
        payload.put("id", event.getId());

        // 父事件 source 为 null，子智能体事件带 source 路径
        if (event.getSource() != null) {
            payload.put("source", event.getSource());
        }

        if (event instanceof TextBlockDeltaEvent e) {
            payload.put("kind", "text");
            payload.put("delta", e.getDelta());

        } else if (event instanceof ThinkingBlockDeltaEvent e) {
            payload.put("kind", "thinking");
            payload.put("delta", e.getDelta());

        } else if (event instanceof ToolCallStartEvent e) {
            payload.put("kind", "tool_start");
            payload.put("toolName", e.getToolCallName());
            payload.put("toolCallId", e.getToolCallId());

        } else if (event instanceof ToolResultEndEvent e) {
            payload.put("kind", "tool_end");
            payload.put("toolCallId", e.getToolCallId());
            payload.put("state", String.valueOf(e.getState()));

        } else if (event instanceof SubagentExposedEvent e) {
            payload.put("kind", "subagent");
            payload.put("subagentId", e.getSubagentId());
            payload.put("agentId", e.getAgentId());
            payload.put("label", e.getLabel());
        }

        try {
            return ServerSentEvent.<String>builder()
                    .data(mapper.writeValueAsString(payload))
                    .build();
        } catch (Exception ex) {
            return ServerSentEvent.<String>builder()
                    .data("{\"type\":\"SERIALIZE_ERROR\"}")
                    .build();
        }
    }
}

2.6本章小结

  • 消息是结果，事件是过程。一次调用的事件序列最终合并为一条 assistant 消息，因此只依靠事件流也可以重建完整消息。
  • 消息内容由 ContentBlock 组成，构造时按角色做严格校验，非法组合会在构建阶段报错。
  • 事件通过 replyId、blockId、toolCallId 三级标识关联，流式内容遵循 start → delta → end。
  • getSource() 区分父子事件：null 是父级，非 null 是子智能体路径。
  • getGenerateReason() 区分正常结束与异常终止，生产环境应当据此分支处理。
  • 官方文档记录了 28 个事件类，但未逐字给出枚举常量清单。实际开发中使用 instanceof 判断事件类更可靠。
练习
  1. 运行 EventObserver，完整记录一次执行的事件顺序。对照本章的事件序列图，标注哪些事件出现了、哪些没有出现，并解释原因。
  2. 在事件观察器中增加对 ToolCallDeltaEvent 的完整参数打印，验证累积后的参数是否为合法 JSON。
  3. 实现 MessageReassembler 的完整版本，用它重建的文本与 Msg.getTextContent() 做逐字比较，验证一致性。
  4. 在 SSE 示例中增加 RequireUserConfirmEvent 的处理分支，让前端在收到确认请求时展示批准与拒绝按钮。
  5. 把 EventObserver 改造成一个交互式命令行程序，支持持续输入多轮对话，并分别显示每一轮的 Token 用量。
