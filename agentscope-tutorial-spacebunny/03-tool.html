工具解决了什么问题

大模型自身掌握的知识来自训练数据，既有时效性限制，也无法访问你的企业内部文档。工具机制正是用来解决这个问题的：你把外部能力注册为工具，模型在需要时主动调用。

更重要的是，注册工具等于扩展了模型的「能力边界」。你注册了什么工具，模型就可能做什么；你没有注册的操作，模型无论如何也做不到。这与传统的程序设计有本质区别：控制权在模型手里。

场景

本章场景

为团队知识助手增加文档检索能力。它需要能够：

  • 在团队文档目录中按关键词检索（search_docs）
  • 读取指定文档的完整内容（read_doc）
  • 获取当前时间（get_current_time），便于在回答中标注时效

本章结束时，助手能回答「支付服务的超时时间是多少」这类需要查文档的问题， 并且引用具体来源。

3.1先讲理论：三个概念

AgentScope 用三个概念组织工具相关内容：

概念含义实现方式
Tool一个可被模型调用的能力继承 ToolBase，或用 @Tool 标注普通 Java 方法
Toolkit工具容器，向模型暴露工具的 JSON Schema，并把调用分派到对应对象new Toolkit() 后注册工具
Tool Group具名的工具集合，可整体激活或停用ToolGroup，常配合元工具使用

每个工具都向模型暴露一份 JSON Schema，描述它的名称、用途与参数结构。模型据此决定何时调用以及如何组织参数。因此工具描述的质量直接决定调用质量：描述含糊，模型就会误用或者不使用。这一点与第三章开头强调的「控制权在模型手里」直接相关，因为模型只能看到 Schema，看不到你的 Java 实现。

模型视角 你注册的工具 ──→ Toolkit 汇总所有 Schema ──→ 组装进请求 │ 模型看到的正是这份 Schema 列表 ↓ 模型返回 tool_use 块 │ 你注册的对象 ←── Toolkit 按名称分派调用 ←─────┘
Toolkit 中的 basic 组

当你只调用 registerTool(Object) 时，该对象上所有 @Tool 方法会自动加入保留名称为 "basic" 的工具组，并且这个组始终激活。理解这一点有助于解释后续工具组的合并规则。

3.2动手：注解方式声明工具

这是最轻量的方式：给普通 Java 方法标注 @Tool，框架按 Java 类型与 description 自动生成 JSON Schema。

KnowledgeTools.javajava
import io.agentscope.core.tool.Tool;
import io.agentscope.core.tool.ToolParam;
import io.agentscope.core.tool.Toolkit;

import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.time.LocalDateTime;
import java.time.ZoneId;
import java.time.format.DateTimeFormatter;
import java.util.List;
import java.util.stream.Collectors;
import java.util.stream.Stream;

/**
 * 团队知识助手的工具集。
 * 这些方法会通过 Toolkit#registerTool 反射式注册。
 */
public class KnowledgeTools {

    /** 团队文档目录。生产环境应当从配置读取。 */
    private static final Path DOC_ROOT = Path.of("./docs");

    /**
     * 按关键词检索团队文档。
     * 描述中明确「何时使用」，有助于模型正确选择工具。
     */
    @Tool(
            name = "search_docs",
            description = "在团队文档目录中按关键词检索文档，返回匹配的文档路径与相关片段。"
                    + "当用户询问具体的配置、参数、流程或规范时使用此工具。",
            readOnly = true,          // 只读工具，权限判定时可自动放行
            concurrencySafe = true)   // 无副作用，允许并发调用
    public String searchDocs(
            @ToolParam(name = "keyword",
                    description = "检索关键词，支持空格分隔的多个词")
            String keyword,
            @ToolParam(name = "limit",
                    description = "最多返回的文档数量，默认 5")
            Integer limit) {

        int max = (limit == null || limit <= 0) ? 5 : limit;

        try (Stream<Path> files = Files.walk(DOC_ROOT)) {
            List<String> results = files
                    .filter(Files::isRegularFile)
                    .filter(p -> p.toString().endsWith(".md"))
                    .filter(p -> {
                        try {
                            return Files.readString(p, StandardCharsets.UTF_8)
                                    .toLowerCase()
                                    .contains(keyword.toLowerCase());
                        } catch (IOException e) {
                            return false;
                        }
                    })
                    .limit(max)
                    .map(p -> {
                        try {
                            String content = Files.readString(p, StandardCharsets.UTF_8);
                            int idx = content.toLowerCase()
                                    .indexOf(keyword.toLowerCase());
                            int from = Math.max(0, idx - 60);
                            int to = Math.min(content.length(), idx + 140);
                            String snippet = content.substring(from, to)
                                    .replace("\n", " ");
                            return "文档：" + DOC_ROOT.relativize(p)
                                    + "\n片段：" + snippet;
                        } catch (IOException e) {
                            return null;
                        }
                    })
                    .filter(java.util.Objects::nonNull)
                    .collect(Collectors.toList());

            if (results.isEmpty()) {
                return "未找到包含「" + keyword + "」的文档。";
            }
            return String.join("\n\n---\n\n", results);

        } catch (IOException e) {
            return "检索失败：" + e.getMessage();
        }
    }

    /** 读取指定文档的完整内容。 */
    @Tool(
            name = "read_doc",
            description = "读取指定文档的完整内容。必须传入 search_docs 返回的路径。",
            readOnly = true,
            concurrencySafe = true)
    public String readDoc(
            @ToolParam(name = "path",
                    description = "文档相对路径，例如 docs/payment/service.md")
            String path) {

        Path target = DOC_ROOT.resolve(path).normalize();
        // 基础路径校验，拒绝越权访问
        if (!target.startsWith(DOC_ROOT.normalize())) {
            return "拒绝访问：路径超出文档目录范围。";
        }
        if (!Files.exists(target)) {
            return "文档不存在：" + path;
        }
        try {
            return Files.readString(target, StandardCharsets.UTF_8);
        } catch (IOException e) {
            return "读取失败：" + e.getMessage();
        }
    }

    /** 获取当前时间，用于在回答中标注信息时效。 */
    @Tool(
            name = "get_current_time",
            description = "获取指定时区的当前时间。当需要标注信息时效性时使用。",
            readOnly = true,
            concurrencySafe = true)
    public String getCurrentTime(
            @ToolParam(name = "timezone",
                    description = "IANA 时区名，例如 Asia/Shanghai")
            String timezone) {
        return LocalDateTime.now(ZoneId.of(timezone))
                .format(DateTimeFormatter.ISO_LOCAL_DATE_TIME);
    }

    /** 组装并返回注册好的 Toolkit。 */
    public static Toolkit create() {
        Toolkit toolkit = new Toolkit();
        toolkit.registerTool(new KnowledgeTools());
        return toolkit;
    }
}

@Tool 常用属性

属性类型说明
nameString工具名称，缺省使用方法名
descriptionString面向模型的用途说明，决定调用质量
readOnlyboolean是否只读，缺省 false。只读工具在权限判定中可被自动放行
concurrencySafeboolean是否允许并发调用，缺省 false
stateInjectedboolean注入 AgentState 作为额外参数，缺省 false
dangerousFilesString[]追加自定义危险文件路径
dangerousDirectoriesString[]追加自定义危险目录路径
converterClass自定义返回值到 ToolResultBlock 的转换
描述写法直接影响调用准确率

请对比本章示例中两个描述的差异：search_docs 的描述说明了「在哪里检索」与「何时使用」，而一个只写「搜索文档」的描述会让模型在很多场景下不知道该不该调用它。推荐做法是描述中包含用途与触发条件两部分。

运行与观察

AgentWithTools.javajava
import io.agentscope.core.ReActAgent;
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.event.AgentEventType;
import io.agentscope.core.event.TextBlockDeltaEvent;
import io.agentscope.core.event.ToolCallEndEvent;
import io.agentscope.core.event.ToolCallStartEvent;
import io.agentscope.core.event.ToolResultEndEvent;
import io.agentscope.core.message.Msg;
import io.agentscope.core.message.UserMessage;
import java.util.List;

public class AgentWithTools {

    public static void main(String[] args) {
        ReActAgent agent = ReActAgent.builder()
                .name("kb-assistant")
                .sysPrompt(jt(24,
                        "你是一个团队知识助手。",
                        "回答前先检索文档，不要凭记忆作答。",
                        "引用内容时必须标明来源文档路径。"))
                .model("dashscope:qwen-plus")
                .toolkit(KnowledgeTools.create())
                .build();

        // 通过事件流观察工具调用过程
        agent.streamEvents(List.of(
                        new UserMessage("支付服务的超时时间是多少？")))
                .doOnNext(event -> {
                    if (event.getType() == AgentEventType.TEXT_BLOCK_DELTA) {
                        System.out.print(((TextBlockDeltaEvent) event).getDelta());
                    } else if (event.getType() == AgentEventType.TOOL_CALL_START) {
                        System.out.println("\n〔调用〕"
                                + ((ToolCallStartEvent) event).getToolCallName());
                    } else if (event.getType() == AgentEventType.TOOL_CALL_END) {
                        ToolCallEndEvent e = (ToolCallEndEvent) event;
                        System.out.println("〔参数〕" + e.getToolCallName());
                    } else if (event.getType() == AgentEventType.TOOL_RESULT_END) {
                        System.out.println("〔返回状态〕"
                                + ((ToolResultEndEvent) event).getState());
                    }
                })
                .blockLast();

        // 也可静默执行，只看结果
        Msg answer = agent.call(List.of(
                        new UserMessage("数据库连接池的默认大小是多少？")),
                RuntimeContext.builder()
                        .userId("zhangsan")
                        .sessionId("s-002")
                        .build())
                .block();
        System.out.println("\n" + answer.getTextContent());
    }
}

3.3动手：继承 ToolBase

注解方式覆盖了大部分需求，然而它有三个无法表达的场合：需要基于实际输入做权限判定、需要把执行权交给外部系统、需要复杂的手写参数结构。遇到这三种情况时，应当改用 ToolBase。

ToolBaseExample.javajava
import io.agentscope.core.message.TextBlock;
import io.agentscope.core.message.ToolResultBlock;
import io.agentscope.core.permission.PermissionBehavior;
import io.agentscope.core.permission.PermissionDecision;
import io.agentscope.core.tool.ToolBase;
import io.agentscope.core.tool.ToolCallParam;
import io.agentscope.core.tool.Toolkit;
import reactor.core.publisher.Mono;

import java.util.List;
import java.util.Map;

public class ToolBaseExample {

    /**
     * 自定义工具：删除文档。
     * 这个操作不可逆，因此通过 checkPermissions 做严格的输入分析。
     */
    public static class DeleteDocTool extends ToolBase {

        public DeleteDocTool() {
            super(ToolBase.builder()
                    .name("delete_doc")
                    .description("删除指定文档。此操作不可撤销，仅在用户明确要求时使用。")
                    .inputSchema(Map.of(
                            "type", "object",
                            "properties", Map.of(
                                    "path", Map.of(
                                            "type", "string",
                                            "description", "文档相对路径"),
                                    "confirm", Map.of(
                                            "type", "boolean",
                                            "description", "必须为 true 才执行")),
                            // 两个参数都是必填，模型必须显式提供
                            "required", List.of("path", "confirm")))
                    .readOnly(false)
                    .concurrencySafe(false));
        }

        /**
         * 运行时权限检查：基于实际输入判定，而非仅依赖规则。
         * 这项检查不可被 BYPASS 模式绕过。
         */
        @Override
        public Mono<PermissionDecision> checkPermissions(
                Map<String, Object> toolInput,
                io.agentscope.core.permission.PermissionContextState context) {

            String path = (String) toolInput.get("path");
            Object confirm = toolInput.get("confirm");

            // 未显式确认则要求人工审批
            if (!Boolean.TRUE.equals(confirm)) {
                return Mono.just(PermissionDecision.ask(
                        "删除文档需要显式确认：" + path));
            }

            // 生产环境相关路径直接拒绝
            if (path != null && path.startsWith("prod/")) {
                return Mono.just(PermissionDecision.deny(
                        "禁止删除生产环境文档：" + path));
            }

            return Mono.just(PermissionDecision.allow("已确认的文档删除"));
        }

        @Override
        public Mono<ToolResultBlock> callAsync(ToolCallParam param) {
            String path = (String) param.getInput().get("path");

            // 真实实现中在这里执行删除逻辑
            return Mono.just(ToolResultBlock.builder()
                    .id(param.getId())
                    .name(getName())
                    .output(List.of(TextBlock.builder()
                            .text("已删除文档：" + path)
                            .build()))
                    .build());
        }
    }

    /**
     * 外部执行工具：把实际执行交给智能体之外的系统。
     * 设置 externalTool(true) 后不实现 callAsync。
     */
    public static class HumanApprovalTool extends ToolBase {

        public HumanApprovalTool() {
            super(ToolBase.builder()
                    .name("human_approval")
                    .description("请求人工审批一项敏感操作。由外部人员实际执行。")
                    .inputSchema(Map.of(
                            "type", "object",
                            "properties", Map.of(
                                    "action", Map.of("type", "string"),
                                    "reason", Map.of("type", "string")),
                            "required", List.of("action", "reason")))
                    .readOnly(false)
                    .concurrencySafe(true)
                    .externalTool(true));   // 执行权交给外部
        }

        @Override
        public Mono<PermissionDecision> checkPermissions(
                Map<String, Object> toolInput,
                io.agentscope.core.permission.PermissionContextState context) {
            return Mono.just(PermissionDecision.allow("外部执行分发始终放行"));
        }
    }

    public static void main(String[] args) {
        Toolkit toolkit = new Toolkit();
        toolkit.registerTool(new DeleteDocTool());
        toolkit.registerTool(new HumanApprovalTool());

        ReActAgentHolder.printToolNames(toolkit);
    }

    /** 仅用于演示：打印已注册的工具名 */
    static class ReActAgentHolder {
        static void printToolNames(Toolkit toolkit) {
            System.out.println("已注册工具组数量："
                    + toolkit.getToolGroupNames().size());
        }
    }
}

ToolBase 属性与方法

暴露给模型与运行时的属性：

方法说明
getName()面向模型的工具名
getDescription()面向模型的用途说明
getParameters()描述参数的 JSON Schema
isReadOnly()是否只读无副作用
isConcurrencySafe()是否允许并发调用
isExternalTool()执行权是否交给外部
isStateInjected()是否注入 AgentState
isMcp() / getMcpName()是否来自 MCP 服务器及其名称

与执行流程及权限系统集成的方法：

方法必需说明
checkPermissions(toolInput, context)是执行前权限检查，返回 Mono<PermissionDecision>
callAsync(param)否执行逻辑，返回 Mono<ToolResultBlock>。外部执行工具不实现此方法
matchRule(ruleContent, toolInput)否自定义规则匹配逻辑，返回 boolean
generateSuggestions(toolInput)否根据当前调用生成建议规则，返回 List<PermissionRule>
PermissionDecision 的四个工厂方法

allow(message)、deny(message)、ask(message)、passthrough(message)。前三者是最终决策；passthrough 表示工具自己不决定，由引擎继续评估规则与模式。第六章会详细讲解整个权限判定流程。

3.4动手：为工具注入业务上下文

真实项目中的工具往往需要访问数据库连接、租户配置、审计器这类业务对象。如果让工具自己从全局单例里查找，那么单元测试会变得困难，多租户场景下也容易串数据。因此 AgentScope 提供了两条注入路径，让业务对象随调用一起传入。

方式一：注解工具自动注入

在方法参数上声明一个业务类型，框架会自动从 RuntimeContext 的类型化属性槽中取值。工具自身完全不需要查找逻辑。

TenantAwareTools.javajava
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.message.Msg;
import io.agentscope.core.message.UserMessage;
import io.agentscope.core.tool.Tool;
import io.agentscope.core.tool.ToolParam;
import io.agentscope.core.tool.Toolkit;
import java.util.List;

/** 业务配置对象，由调用方放入 RuntimeContext */
public class TenantConfig {
    private final String tenantId;
    private final String region;

    public TenantConfig(String tenantId, String region) {
        this.tenantId = tenantId;
        this.region = region;
    }

    public String getTenantId() { return tenantId; }
    public String getRegion() { return region; }
}

public class TenantAwareTools {

    /**
     * 注意 query 方法的参数声明了 TenantConfig 类型。
     * 框架会自动从 RuntimeContext 供给，模型不需要也看不到这个参数。
     */
    @Tool(
            name = "query_knowledge_base",
            description = "查询当前租户的知识库。",
            readOnly = true)
    public String query(
            @ToolParam(name = "question", description = "查询内容")
            String question,

            // 类型化参数：框架自动注入，不出现在模型的工具 Schema 中
            TenantConfig config) {

        return "租户 " + config.getTenantId()
                + "（区域 " + config.getRegion() + "）的知识库查询： " + question;
    }

    public static void main(String[] args) {
        Toolkit toolkit = new Toolkit();
        toolkit.registerTool(new TenantAwareTools());

        ReActAgentHolder agent = ReActAgentHolder.build(toolkit);

        // 调用时放入类型化属性
        RuntimeContext ctx = RuntimeContext.builder()
                .userId("zhangsan")
                .sessionId("s-001")
                // 类型化槽：key 为 Class，工具按参数类型取值
                .put(TenantConfig.class, new TenantConfig("acme", "cn-north"))
                .build();

        Msg reply = agent.call(List.of(
                new UserMessage("我们的数据保留策略是什么？")), ctx).block();

        System.out.println(reply.getTextContent());
    }

    /** 简化的构建辅助 */
    static class ReActAgentHolder {
        static ReActAgentHolder build(Toolkit toolkit) {
            return new ReActAgentHolder(toolkit);
        }

        private final io.agentscope.core.ReActAgent agent;

        ReActAgentHolder(Toolkit toolkit) {
            this.agent = io.agentscope.core.ReActAgent.builder()
                    .name("kb-assistant")
                    .sysPrompt("你是一个团队知识助手，回答前先查询知识库。")
                    .model("dashscope:qwen-plus")
                    .toolkit(toolkit)
                    .build();
        }

        Msg call(List<UserMessage> msgs, RuntimeContext ctx) {
            return agent.call(msgs, ctx).block();
        }
    }
}

方式二：ToolBase 中读取上下文

继承 ToolBase 时，通过 ToolCallParam.getRuntimeContext() 获取。

ToolCallParamExample.javajava
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.message.ToolResultBlock;
import io.agentscope.core.message.TextBlock;
import io.agentscope.core.permission.PermissionDecision;
import io.agentscope.core.tool.ToolBase;
import io.agentscope.core.tool.ToolCallParam;
import reactor.core.publisher.Mono;
import java.util.List;
import java.util.Map;

public class ToolCallParamExample {

    public static class AuditTool extends ToolBase {

        public AuditTool() {
            super(ToolBase.builder()
                    .name("write_audit_log")
                    .description("写入审计日志。框架自动附加当前用户与请求标识。")
                    .inputSchema(Map.of(
                            "type", "object",
                            "properties", Map.of(
                                    "event", Map.of("type", "string",
                                            "description", "事件描述")),
                            "required", List.of("event")))
                    .readOnly(false)
                    .concurrencySafe(true));
        }

        @Override
        public Mono<PermissionDecision> checkPermissions(
                Map<String, Object> toolInput,
                io.agentscope.core.permission.PermissionContextState context) {
            return Mono.just(PermissionDecision.allow("审计写入始终放行"));
        }

        @Override
        public Mono<ToolResultBlock> callAsync(ToolCallParam param) {
            // ToolCallParam 提供多种访问入口
            RuntimeContext rc = param.getRuntimeContext();

            String userId = (rc != null) ? rc.getUserId() : "unknown";
            String sessionId = (rc != null) ? rc.getSessionId() : "unknown";
            String requestId = (rc != null) ? rc.get("request_id") : null;

            // 也可以取出类型化属性
            TenantConfig cfg = (rc != null) ? rc.get(TenantConfig.class) : null;

            String entry = String.format(
                    "user=%s session=%s requestId=%s tenant=%s event=%s",
                    userId, sessionId, requestId,
                    (cfg != null ? cfg.getTenantId() : "-"),
                    param.getInput().get("event"));

            System.out.println("[审计] " + entry);

            return Mono.just(ToolResultBlock.builder()
                    .id(param.getId())
                    .name(getName())
                    .output(List.of(TextBlock.builder()
                            .text("已记录审计日志")
                            .build()))
                    .build());
        }
    }
}

ToolCallParam 提供以下访问入口：

方法说明
getInput()本次调用的参数 Map
getRuntimeContext()本次调用的上下文，新代码优先使用此方法
getId()工具调用标识，用于构造结果块
getAgent()调用方 Agent 引用
getToolUseBlock()原始的工具调用块
getEmitter()事件发射器，可主动发出事件
getContext()已废弃，请改用 getRuntimeContext()

3.5动手：工具组与元工具

工具数量增加之后，新的问题出现了：模型的上下文被大量无关工具占用，选择准确率随之下降。与此同时，把所有工具一次性注册也是常见做法，这在工具数量较少时没有问题。ToolGroup 与元工具正是为这个阶段设计的，它们让模型只在需要时看到当前任务相关的工具。

定义工具组

ToolGroupDemo.javajava
import io.agentscope.core.ReActAgent;
import io.agentscope.core.tool.ToolGroup;
import io.agentscope.core.tool.ToolGroupScope;
import io.agentscope.core.tool.Toolkit;

// 假设已有这些工具类
// import com.example.tools.DatabaseTools;
// import com.example.tools.DeploymentTools;
// import com.example.tools.QueryTools;

public class ToolGroupDemo {

    public static void main(String[] args) {
        Toolkit toolkit = new Toolkit();

        // 基础查询工具：注册后自动进入 "basic" 组，始终激活
        toolkit.registerTool(new QueryTools());

        // 数据库工具组：默认不激活
        ToolGroup database = new ToolGroup(
                "database",
                "数据库操作工具：查询、迁移、索引重建。",
                ToolGroupScope.SESSION,
                /* active = */ false);
        database.addTool("db_query");
        database.addTool("db_migrate");
        toolkit.registerTool(new DatabaseTools());
        toolkit.registerToolGroup(database);

        // 部署工具组：默认不激活
        ToolGroup deployment = new ToolGroup(
                "deployment",
                "服务部署与回滚工具。仅在用户明确要求部署时使用。",
                ToolGroupScope.SESSION,
                /* active = */ false);
        deployment.addTool("deploy");
        deployment.addTool("rollback");
        toolkit.registerTool(new DeploymentTools());
        toolkit.registerToolGroup(deployment);

        ReActAgent agent = ReActAgent.builder()
                .name("ops-assistant")
                .sysPrompt(jt(24,
                        "你是运维助手。",
                        "涉及生产环境的操作必须先说明影响范围。"))
                .model("dashscope:qwen-plus")
                .toolkit(toolkit)
                // 开启元工具后，模型可以自行查看与切换工具组
                .enableMetaTool(true)
                .build();
    }

    // 占位类，实际使用时替换为你的工具实现
    static class QueryTools {}
    static class DatabaseTools {}
    static class DeploymentTools {}
}
ToolGroupScope作用域适用场景
SESSION会话级同一会话内共享激活状态
AGENT智能体级整个智能体实例共享
USER用户级同一用户的全部会话共享

元工具的行为

开启 enableMetaTool(true) 后，Toolkit 会注册两个元工具：list_tools 让模型查看可用工具，activate_group 让模型切换当前激活的工具组。此外，当存在额外工具组或技能时，Toolkit 还会自动注册 load_skill_through_path。

工具数量与选择准确率

当工具数量超过一定规模时，模型的工具选择准确率会明显下降。官方提供工具组机制正是为了应对这个情况。如果你的工具集已经超过十几个，建议按场景分组，而不是把所有工具一次性注册。

3.6动手：接入 MCP 工具

前六个示例中的工具全部由我们自己编写。然而实际工作中，大量第三方能力已经以 MCP Server 的形式提供，接入它们不需要写 Java 代码，只需要声明连接信息。

STDIO 方式

McpStdioDemo.javajava
import io.agentscope.core.tool.Toolkit;
import io.agentscope.core.tool.mcp.McpClientBuilder;
import io.agentscope.core.tool.mcp.McpClientWrapper;

public class McpStdioDemo {

    public static void main(String[] args) {
        // 以子进程方式启动本地 MCP Server
        McpClientWrapper filesystem = McpClientBuilder.stdio()
                .name("filesystem")
                .command("npx")
                .args("-y", "@modelcontextprotocol/server-filesystem", "/my/project")
                .build();

        Toolkit toolkit = new Toolkit();
        toolkit.registerTool(new QueryTools());

        // 注册 MCP 客户端：注意这是异步操作，需要等待完成
        toolkit.registerMcpClient(filesystem).block();

        // 此后模型即可看到 filesystem MCP 提供的全部工具
        System.out.println("工具注册完成");
    }

    static class QueryTools {}
}

3.8本章小结

  • 工具决定智能体的能力边界。注册了什么，它就可能做什么。
  • 工具描述的质量直接决定调用准确率，描述中应包含用途与触发条件。
  • 轻量需求用 @Tool 注解；需要自定义权限、外部执行或复杂参数结构时继承 ToolBase。
  • checkPermissions 基于实际输入判定，且不可被 BYPASS 模式绕过，这是实现严格安全策略的正确位置。
  • 工具通过 JSON Schema 暴露给模型；工具数量过多会降低选择准确率，可用 ToolGroup 分组管理。
  • 业务上下文有两条注入路径：注解工具通过类型化参数自动注入，ToolBase 通过 ToolCallParam.getRuntimeContext() 读取。
练习
  1. 为知识助手增加一个 list_docs 工具，列出文档目录下的所有文档名，并描述它与 search_docs 的使用场景差异。
  2. 把 search_docs 的 description 改成一个含糊的版本（例如只写「搜索」），然后向助手提问三个不同类型的问题，观察调用准确率的变化。
