1.1先讲理论：ReAct 循环

很多初次接触智能体框架的读者会以为「智能体」是一个更复杂的聊天接口。实际上，智能体的本质是一个会自己决定是否调用工具的循环。这个循环被称为 ReAct：Reason（推理）加 Act（行动）。

它的执行过程是这样的：

组装上下文

把系统提示词、历史消息、可用工具的 JSON Schema 组合成一次模型请求。

调用模型

大模型返回文本；如果它认为需要使用工具，会同时返回工具调用意图。

判断分支

如果模型只返回文本，说明它已经给出了最终答案，循环结束。如果模型返回了工具调用，则进入行动阶段。

执行工具

框架执行模型请求的工具，把执行结果作为新消息追加到上下文里。

回到第一步

模型看到工具结果，继续推理。这个过程会重复若干轮，直到模型不再请求工具，或者达到最大迭代次数。

ReAct 主循环 ┌─→ 组装上下文 ──→ 调用模型 ──┐ │ ↑ │ │ │ ↓ │ 追加工具结果 模型返回内容 │ │ │ └────────┤ ┌────────┴────────┐ │ │ │ 有工具调用 仅文本 达到上限 │ │ │ 执行工具 结束 结束

理解这个循环有一个关键点：模型自己决定是否使用工具，而不是你的代码决定。你注册了搜索工具，模型可能这一轮不用，下一轮才用。因此你写的代码本质上是在描述「能力边界」，而不是编排执行流程。

为什么这一点很重要

传统程序的控制流由开发者决定，而智能体的控制流由模型决定。这带来一个直接后果： 你需要为「模型做出意外决定」做好准备——第三章的权限系统、第六章的人工确认机制， 都是为了处理模型可能执行的非预期操作。

循环的终止条件

循环会在三种情况下结束：

终止原因枚举值含义
模型给出最终答案MODEL_STOP正常结束，最常见的情况
需要外部确认而暂停TOOL_SUSPENDED权限系统要求人工确认，或工具声明为外部执行
达到迭代上限MAX_ITERATIONS模型陷入循环，默认上限是 10 轮，可用 maxIters 调整
被外部中断INTERRUPTED调用 interrupt() 停止执行
全部工具被拒绝ALL_TOOLS_DENIED用户拒绝了本轮全部工具调用

这些原因可以通过返回的 Msg.getGenerateReason() 读取。在生产环境中，你通常需要根据这些值采取不同动作，例如迭代上限触发时记录告警，权限暂停时向用户推送确认请求。

1.2Agent 的三个方法

AgentScope Java 的 Agent 是接口，ReActAgent 是默认实现。接口组合了三个能力接口：CallableAgent、StreamableAgent、ObservableAgent。你最常使用的是下面三个方法。

方法返回类型用途
call(List<Msg>[, RuntimeContext])Mono<Msg>执行完整循环，返回最终消息。适合后端批处理与集成测试
streamEvents(Msg | List<Msg>)Flux<AgentEvent>增量输出类型化事件。适合命令行交互、网页与桌面界面
observe(Msg | List<Msg>)Mono<Void>只把消息写入上下文，不触发推理。适合多智能体之间传递信息
返回类型是 Reactor 类型

所有方法都返回 Mono 或 Flux，这是 Project Reactor 的类型。这意味着 AgentScope Java 的执行模型是响应式的，默认使用非阻塞 IO。在同步代码中调用时，末尾的 .block() 会阻塞等待结果，因此请不要在响应式线程内部调用 .block()。本教程的示例为了便于阅读，统一使用 .block()。

1.3动手：构建知识助手

准备模型

导出环境变量 DASHSCOPE_API_KEY，确认 SDK 版本为 2.0.1。

创建类

新建 src/main/java/com/example/kb/FirstAgent.java，写入下方代码。

运行

使用 mvn compile exec:java 或 IDE 运行 main 方法。

完整代码

FirstAgent.javajava
import io.agentscope.core.ReActAgent;
import io.agentscope.core.message.Msg;
import io.agentscope.core.message.UserMessage;
import java.util.List;

public class FirstAgent {

    public static void main(String[] args) {
        // builder() 返回一个构建器，build() 产出可用的 Agent 实例
        ReActAgent agent = ReActAgent.builder()
                // name 是智能体标识，用于消息记录与日志
                .name("kb-assistant")
                // sysPrompt 是基础系统提示词，决定智能体的角色与行为约束
                .sysPrompt(jt(24,
                        "你是一个团队知识助手。",
                        "回答时保持简洁，只陈述你确信的内容。",
                        "如果不确定，请明确说明。"))
                // model 接受 "provider:model" 字符串，由 ModelRegistry 解析，
                // 并自动读取对应的 API Key 环境变量
                .model("dashscope:qwen-plus")
                .build();

        // call() 执行完整的推理-行动循环，返回最终消息
        Msg reply = agent.call(List.of(
                new UserMessage("什么是幂等性？")
        )).block();

        System.out.println(reply.getTextContent());
    }
}
关于三引号文本块

Java 15 引入的文本块（text block）非常适合写多行系统提示词。它保留了换行与缩进，比一长串字符串拼接可读得多。注意文本块的缩进会被去除到公共前缀，因此要注意首尾是否有意外空格。

切换模型服务商

如果你不使用通义千问，只需修改两处：.model() 中的字符串，以及环境变量名称。框架通过前缀识别服务商。

切换模型java
// DashScope（通义千问）—— DASHSCOPE_API_KEY
.model("dashscope:qwen-plus")

// OpenAI —— OPENAI_API_KEY
.model("openai:gpt-5.5")

// Anthropic —— ANTHROPIC_API_KEY
.model("anthropic:claude-sonnet-4-5")

// Google Gemini —— GEMINI_API_KEY
.model("gemini:gemini-2.0-flash")

// DeepSeek —— DEEPSEEK_API_KEY
.model("deepseek:deepseek-v4-flash")

// 本地 Ollama，无需 API Key
.model("ollama:llama3")

使用字符串形式的前提是对应的 agentscope-extensions-model-* 模块在 classpath 中。例如使用 Ollama 需要引入 agentscope-extensions-model-ollama。

需要精细控制时使用显式构造

当你需要设置超时、自定义端点或指定采样参数时，可以直接构造模型对象。

显式构造模型java
import io.agentscope.core.ReActAgent;
import io.agentscope.core.model.GenerateOptions;
import io.agentscope.extensions.model.dashscope.DashScopeChatModel;
import io.agentscope.extensions.model.dashscope.formatter.DashScopeChatFormatter;

public class ExplicitModelAgent {
    public static void main(String[] args) {
        DashScopeChatModel model = DashScopeChatModel.builder()
                .apiKey(System.getenv("DASHSCOPE_API_KEY"))
                .modelName("qwen-plus")
                .stream(true)
                .formatter(new DashScopeChatFormatter())
                .defaultOptions(GenerateOptions.builder()
                        .temperature(0.2)
                        .maxTokens(1024)
                        .build())
                .build();

        ReActAgent agent = ReActAgent.builder()
                .name("kb-assistant")
                .sysPrompt("你是一个严谨的技术助手。")
                .model(model)      // 传入实例而非字符串
                .build();
    }
}

1.4运行与观察

上面的代码只会输出最终答案。但调试智能体时，你通常需要知道它经历了什么。因此 AgentScope 提供了事件流接口。

流式观察java
import io.agentscope.core.ReActAgent;
import io.agentscope.core.event.AgentEventType;
import io.agentscope.core.event.TextBlockDeltaEvent;
import io.agentscope.core.event.ThinkingBlockDeltaEvent;
import io.agentscope.core.event.ToolCallStartEvent;
import io.agentscope.core.message.UserMessage;

public class StreamObserver {

    public static void main(String[] args) {
        ReActAgent agent = ReActAgent.builder()
                .name("kb-assistant")
                .sysPrompt("你是一个团队知识助手。")
                .model("dashscope:qwen-plus")
                .build();

        agent.streamEvents(new UserMessage("用三句话解释什么是幂等性"))
                .doOnNext(event -> {
                    if (event.getType() == AgentEventType.TEXT_BLOCK_DELTA) {
                        // 文本增量：像打字机一样逐段输出
                        System.out.print(((TextBlockDeltaEvent) event).getDelta());
                    } else if (event.getType() == AgentEventType.THINKING_BLOCK_DELTA) {
                        // 思考增量：部分模型会输出推理过程
                        System.out.print("〔思考〕"
                                + ((ThinkingBlockDeltaEvent) event).getDelta());
                    } else if (event.getType() == AgentEventType.TOOL_CALL_START) {
                        // 工具调用开始
                        System.out.println("\n〔调用工具〕"
                                + ((ToolCallStartEvent) event).getToolCallName());
                    }
                })
                .blockLast();
    }
}

运行后会看到类似这样的输出：

输出示例text
〔思考〕用户问到了幂等性，这是一个计算机科学概念。我应该先给出定义，
〔思考〕然后说明它的应用场景，最后给出一个例子。
幂等性是指同一个操作执行一次和执行多次的效果相同。

〔调用工具〕get_current_time
〔调用工具结束〕2026-07-10T14:23:11
上面提到的日期以当前时间为准。

这个输出让你看清了三件事：模型先做推理、再决定调用工具、最后基于工具结果继续生成。第二章会系统讲解全部 28 种事件类型，这里先建立一个直观印象即可。

关于思考过程

并非所有模型都会输出推理过程。THINKING_BLOCK_DELTA 事件只在模型 启用了思考模式时出现。通义千问的 thinking 系列模型可以通过 enableThinking(true) 与 thinkingBudget() 控制。

1.5为什么是无状态的

这是 AgentScope Java 2.0 最重要的设计决策之一，也是初学者最容易误解的地方。你可能会想：聊天需要记住上文，那 Agent 对象必然要保存对话历史。实际情况是Agent 实例不保存任何会话状态。

原因是生产环境中的智能体服务通常要同时服务大量用户。如果状态保存在实例字段里，那么每个用户都需要一个实例，而实例又持有模型连接等重量级资源，成本无法接受。因此框架把每次调用的状态通过 RuntimeContext 传递，Agent 本身保持无状态。

单实例服务多用户java
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.message.UserMessage;
import io.agentscope.core.state.JsonFileAgentStateStore;
import io.agentscope.core.ReActAgent;
import java.nio.file.Paths;
import java.util.List;

public class MultiUserAgent {

    public static void main(String[] args) {
        // 应用启动时创建一个实例即可，全局复用
        ReActAgent agent = ReActAgent.builder()
                .name("kb-assistant")
                .sysPrompt("你是一个团队知识助手。")
                .model("dashscope:qwen-plus")
                // 配置状态存储后，Agent 会为每个 (userId, sessionId)
                // 自动加载与保存会话状态
                .stateStore(new JsonFileAgentStateStore(
                        Paths.get(System.getProperty("user.home"),
                                  ".agentscope/sessions")))
                .build();

        // 张三的会话
        agent.call(List.of(new UserMessage("我叫张三，在负责支付模块。")),
                RuntimeContext.builder()
                        .userId("zhangsan")
                        .sessionId("s-001")
                        .build())
                .block();

        // 李四的会话，与张三完全隔离
        agent.call(List.of(new UserMessage("我叫李四，在负责风控模块。")),
                RuntimeContext.builder()
                        .userId("lisi")
                        .sessionId("s-001")   // sessionId 相同也无妨
                        .build())
                .block();

        // 张三回到原会话，问「我刚才说我负责什么」
        Msg reply = agent.call(List.of(new UserMessage("我刚才说我负责什么？")),
                RuntimeContext.builder()
                        .userId("zhangsan")
                        .sessionId("s-001")
                        .build())
                .block();

        System.out.println(reply.getTextContent());   // 输出：支付模块
    }
}

这段代码展示了三个要点：

  • Agent 实例可以在启动时创建一次，之后所有请求都复用它。
  • (userId, sessionId) 决定加载哪一份会话状态，不同组合之间完全隔离。
  • 同一组合的调用会串行执行，不同组合则可以并发执行。
不配置 stateStore 会怎样

默认情况下 Agent 不会保存会话状态，每次调用都是全新的对话。如果你需要多轮对话能力，必须显式配置 stateStore(...)。这是初学者最常见的困惑来源：明明前一轮告诉了它名字，下一轮却说不记得。

1.7本章小结

回顾一下本章的核心内容：

  • ReAct 循环是智能体的本质：推理、行动、观察、再推理，由模型决定何时停止。
  • call() 返回最终消息，streamEvents() 输出事件流，observe() 只写入上下文。
  • Agent 实例无状态。状态由 AgentStateStore 按 (userId, sessionId) 管理，这是水平扩展的前提。
  • 不配置 stateStore 就没有多轮对话能力，这是最常见的困惑来源。
  • 所有方法返回 Reactor 类型，同步调用需要 .block()。
练习
  1. 修改系统提示词，让它扮演一个只回答技术问题的助手，并且每次回答都必须给出来源说明。运行几次观察行为差异。
  2. 在示例中不配置 stateStore，第一轮告诉它「我叫李四」，第二轮问「我叫什么」。观察输出，然后解释原因。
  3. 加上 stateStore 重新运行，确认第二轮能正确记住名字。
  4. 尝试切换到 openai:gpt-5.5，如果你没有对应密钥，观察报错信息并查阅官方文档中的模型配置章节。
  5. 阅读 stateStore 生成的文件目录（默认在 ~/.agentscope/sessions/），找到 s-001 对应的 JSON 文件，看看会话内容是如何存储的。
