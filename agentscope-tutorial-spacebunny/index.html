这份教程怎么用

AgentScope Java 2.0 的能力非常多，如果按 API 手册的顺序逐个阅读，很容易陷入「知道每个类存在、但不知道它们之间如何协作」的状态。因此本教程采用场景驱动的顺序：每一章解决一个真实问题，而你需要的能力恰好由这一章引入。

前五章属于内核部分，读完即可独立开发单智能体应用；第六章到第十二章是 Harness 工程化层，决定了你的智能体能否支撑长时间运行的复杂任务；第十三章与第十四章面向生产环境。如果你时间有限，建议先读完第一章与第三章，再按需查阅其余章节。

贯穿教程的示例场景

一个团队知识助手

本教程会反复构建同一个系统：团队知识助手。它读取团队的 Markdown 文档，回答问题并给出引用出处；它能记住每位同事的偏好；它把耗时任务委托给子智能体；它对删除类操作请求人工确认。

之所以选择这个场景，是因为它足够贴近企业中的真实需求，同时又能在每一章自然地扩展。第 1 章它只是一个问答机器人，第 8 章之后它开始具备长期记忆与技能积累，第 11 章它可以并行分析多个文档，到第 14 章它成为可以水平扩展的服务。

依赖选择说明

agentscope-harness 会自动引入 agentscope-core，前者是推荐的入口，后者只提供推理内核。如果你只需要最轻量的 ReAct 循环，可以只依赖 agentscope-core。模型实现位于独立的 agentscope-extensions-model-* 模块，因此引入哪一个模型取决于你选择哪家服务商。

配置 API Key

模型凭证从环境变量读取。使用 ModelRegistry 的字符串形式时，框架会自动读取对应变量，因此代码里不需要出现密钥字面量。

终端bash
# DashScope（通义千问）
export DASHSCOPE_API_KEY=sk-xxxxxxxx

# 如果改用其他服务商，替换模型 id 并导出对应变量即可
export OPENAI_API_KEY=sk-xxxxxxxx
export ANTHROPIC_API_KEY=sk-ant-xxxxxxxx
export GEMINI_API_KEY=xxxxxxxx
export DEEPSEEK_API_KEY=sk-xxxxxxxx
不要把密钥写进源码

多租户场景下，每个租户使用各自的密钥，此时应当通过 ModelCreationContext 把密钥传入 ModelRegistry.resolve(modelId, context)，而不是为每个租户创建独立的环境变量。第五章会给出完整示例。

AgentScope 2.0 特性全景

这一节把 AgentScope Java 2.0 的全部能力列举出来，方便你对照检查。后续每一章会深入其中的一个分组。

一、推理内核

ReActAgent 无状态推理
实例本身不持有会话状态，状态经 Reactor Context 传递，因此单实例可并发服务多个 (userId, sessionId) 组合。
统一 call / streamEvents
call() 返回最终 Msg，streamEvents() 输出类型化事件流。observe() 只写入上下文而不触发推理。
ContentBlock 消息模型
TextBlock、DataBlock、ToolUseBlock、ToolResultBlock、HintBlock、ThinkingBlock，构造时按角色做类型校验。
28 种类型化事件
生命周期、文本增量、思考增量、工具调用、工具结果、模型调用、人工确认、子智能体暴露，覆盖执行全过程的观测需求。
结构化输出
传入 Java record 或 JSON Schema。模型支持原生 response_format 时直接使用，否则自动降级为合成工具调用。
中断与优雅停止
interrupt() 按会话粒度停止执行，状态自动保存，下次调用从中断点继续。
模型容错
maxRetries() 与 fallbackModel() 支持自动重试与故障转移，failoverListener 提供切换回调。
统一模型抽象
Credential + ModelRegistry 覆盖 Qwen、OpenAI、Anthropic、Gemini、DeepSeek、Ollama、GLM、Kimi、Minimax 等服务商。

二、工具与协议

@Tool 注解工具
普通 Java 类的方法标注 @Tool 与 @ToolParam 即可，框架按类型自动生成 JSON Schema。
ToolBase 显式工具
需要自定义权限判定、外部执行模式或复杂参数结构时，继承 ToolBase。
MCP 客户端
支持 STDIO、Streamable HTTP、SSE 三种传输方式，通过 McpClientBuilder 构建后注册到 Toolkit。
工具组与元工具
ToolGroup 按需激活，reset_tools 让模型自行切换工具组，减少无关工具对上下文的干扰。
内置文件工具
read_file、write_file、edit_file、list_files、grep_files、glob_files，强制先读后改并内置缓存。
任务清单工具
TodoTools.todoWrite 让模型自主拆解任务并跟踪进度，配合 TaskReminderMiddleware 保持长任务与计划一致。
异步与定时执行
工具可声明为异步执行并设置唤醒时间，长耗时操作不必阻塞等待。
A2A 与 AG-UI 协议
内置 Agent-to-Agent 互操作能力与 AG-UI 事件适配，便于接入外部智能体平台与前端。

三、Harness 工程化

HarnessAgent
在 ReActAgent 之上组合工作区、记忆、会话持久化、子智能体、沙箱、技能与计划模式，推理内核保持不变。
Workspace 抽象
AGENTS.md、MEMORY.md、skills/、subagents/、tools.json 统一以文件形式保存，每轮重新组装进系统提示词，改文件立即生效。
两层长期记忆
memory/YYYY-MM-DD.md 按日追加事实日志，后台任务合并为 MEMORY.md，每轮注入系统提示词。
上下文压缩
结构化摘要保留任务目标、当前状态、关键结论与后续步骤；超过阈值的工具结果自动落盘，上下文只保留首尾预览。
子智能体编排
声明式 spec 文件加运行时 agent_spawn / agent_send，支持同步阻塞与后台委派，事件流实时转发到父级。
技能系统
四层组合（classpath、远程仓库、workspace、用户级），自我学习闭环为提出、评审、晋升，长期未使用技能自动归档。
Plan Mode
只读的规划阶段，先产出计划文件，经人工确认后再进入执行阶段。
Channel 通道
内置对话界面适配器，支持钉钉、飞书、GitHub、GitLab、企业微信；可自定义通道接入内部系统。

四、生产与分布式

多租户隔离
IsolationScope 支持会话、用户、智能体、全局四个维度，映射为本地路径前缀、KV 命名空间或沙箱状态槽。
状态存储
AgentStateStore 内存、JSON 文件、Redis、MySQL、OSS；按 (userId, sessionId) 自动分区，跨副本恢复会话。
沙箱执行
本地、Docker、Kubernetes、E2B、Daytona、AgentRun 等后端统一接口，支持快照与恢复。
执行守卫
沙箱并发租约机制，支持 Redis SET NX PX 与 MySQL GET_LOCK() 两种实现。
OpenTelemetry 追踪
OtelTracingMiddleware 为智能体生命周期、模型调用、工具执行生成嵌套 span，可上报到 Langfuse 等兼容平台。
优雅启停
GracefulShutdownManager 在进程退出前等待在途调用完成，配合状态存储实现零停机滚动发布。

整体架构

理解下面这张图比记住任何一个类名都重要。AgentScope Java 2.0 的所有能力都挂载在这三个层次上：

Harness 工程化层（HarnessAgent · 面向长时间运行的任务） ├─ Workspace persona · 知识 · 技能 · 子智能体声明 · 工具配置 ├─ Memory & Compaction 长期记忆 · 上下文压缩 · 大结果落盘 ├─ Subagent 声明式 spec · 同步与后台委派 · 事件转发 ├─ Skill 四层组合 · 自我学习闭环 ├─ Plan Mode 只读规划阶段 · 人工确认退出 └─ Filesystem & Sandbox 本地 · 容器 · Kubernetes · 云沙箱 ↓ 通过 Middleware 与 Toolkit 两个通道注入 扩展机制 ├─ Middleware onAgent / onReasoning / onActing / onModelCall / onSystemPrompt └─ Toolkit @Tool · ToolBase · MCP 客户端 · ToolGroup · Skill ↓ ReAct 推理内核（ReActAgent · 无状态，仅负责推理与行动） ├─ Reasoning 组装上下文 → 调用模型 → 流式解码 ├─ Acting 工具调用 · 并发执行 · 权限判定 └─ Message & Event ContentBlock · 28 种 AgentEvent

有两个设计原则值得反复强调。第一，能力挂载在推理循环之外，而不是嵌入其中：无论 Workspace 注入、上下文压缩还是子智能体委派，都发生在 ReAct 循环的特定节点上，推理算法本身保持不变。因此你可以在开发阶段使用最轻量的内核，在生产阶段启用全部工程化能力，业务代码无需重写。

第二，各能力之间互不依赖，它们共享三个对象：RuntimeContext 标识当前这次调用属于谁，Workspace 决定文件读写落在哪里，AgentStateStore 负责状态恢复。你在第八章会看到这条原则如何贯穿整个设计。
