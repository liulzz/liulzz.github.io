13.1 本章场景：网页版客服对话

🎬场景任务

前面的章节都在“命令行里自说自话”。现在要给客服智能体做一个网页聊天界面：用户登录后自动定位到自己的会话；回答逐字流式显示；并且当客服把工单转给“退款专员”子智能体时，界面上要能区分发言人。因此，本章介绍框架的对外服务层——Channel 与 Gateway。

13.2 理论：Channel 是什么

Channel 是智能体与外部用户之间的通信抽象：它负责把“用户 ID + 会话 ID + 文本”交给智能体，并且把回复（或流式事件）送回。框架内置 ChatUiChannel，专为自建网页 / App 前端设计，它的好处是会话路由自动化——每个 userId 自动获得独立 session，无需你手工管理 RuntimeContext：

三行接入聊天HarnessAgent agent = HarnessAgent.builder()
    .name("assistant")
    .sysPrompt("你是一个有用的助手。")
    .model("dashscope:qwen-plus")
    .build();

// 绑定一个 ChatUI channel
ChatUiChannel chat = agent.channel(ChatUiChannel.create());

// 发送消息。每个 userId 自动获得独立的 session
Msg reply = chat.send(SendOptions.userId("user-1"), "你好！").block();

// 同一个用户，同一个 session——对话继续
Msg followUp = chat.send(SendOptions.userId("user-1"), "再多说一些。").block();

13.3 实践：多用户与多会话路由

同一用户可以有多个并行话题（多个会话），用 SendOptions.of(userId, sessionId) 显式指定：

同一用户，两个独立对话chat.send(SendOptions.of("user-1", "session-a"), "话题 A").block();
chat.send(SendOptions.of("user-1", "session-b"), "话题 B").block();

流式输出对应 sendStream：返回事件流，前端按事件类型渲染即可（文本增量对应打字机效果，工具调用对应“正在查询……”的状态提示）。

13.4 实践：Gateway 与子智能体事件

当一个智能体不够用时（例如客服 + 退款专员 + 物流查询员），GatewayBootstrap 负责把多个 agent 挂到同一个服务入口：

Gateway 多智能体挂载GatewayBootstrap gw = GatewayBootstrap.builder()
        .agent("support", csAgent)             // 主客服
        .mainAgent("support")                  // 未指定 agent 时的默认
        .runtimeContextResolver(req ->         // 从请求解析租户上下文
                RuntimeContext.builder(req.callerContext())
                        .put("tenant", resolveTenant(req))
                        .build())
        .build();

ChatUiChannel chat = gw.chatUiChannel();

主智能体把任务转给子智能体时，子智能体的输出会以独立事件流回前端；配合第 10 章的 expose_to_user: true，界面上就能展示“退款专员”的发言身份。渠道层与子智能体之间的桥接需要显式挂载：调用 gw.gatewayBridge() 取得 SubagentGatewayBridge，再通过 setGatewayBridge() 传给智能体，agent_spawn 的 expose_to_user 才能在网关场景生效。

13.5 前端对接建议

网页端只需一个 SSE（Server-Sent Events）连接，把事件按类型渲染：

事件前端处理
文本增量追加到当前气泡（打字机效果）
工具调用开始 / 结束显示状态条（“正在查询工单…”）
需要用户确认渲染确认按钮（第 6 章 HITL）
子智能体发言切换气泡头像与昵称
✍️动手练习 13
  1. 写一个最小 Spring Boot 接口：把 HTTP 消息通过 chat.send() 转给智能体，返回 Msg 文本；
  2. 把接口升级为 SSE，用 sendStream 推送文本增量，在浏览器观察打字机效果；
  3. 用两个浏览器隐身窗口模拟 user-1 与 user-2，验证会话互不串扰；再为 user-1 开两个标签页（不同 sessionId）验证话题隔离。

13.6 本章小结

Channel 把“用户-智能体”的通信标准化，ChatUiChannel 三行接入、会话自动路由；Gateway 则支持多智能体共享入口与子智能体透明转发。至此单实例能力全部讲完——下一章面对真实的流量、故障与租户：上生产。
