7.1 本章场景：审计与可观测

🎬场景任务

合规部门对智能体服务提出三点要求：每一次调用要记录用户与会话；每一次模型调用要统计耗时；全链路要能导出到 tracing 平台分析。这三项需求都不属于业务逻辑，因此正确答案是使用中间件——它们像过滤器一样叠在智能体生命周期上，业务代码零改动。

7.2 理论：六阶段生命周期与洋葱模型

AgentScope 2.0 把智能体一次调用的过程划分为若干拦截点，中间件可以在每个拦截点“包住”内部逻辑：

生命周期结构onAgent                      // 整次调用最外层
  └── ReAct loop（每一轮）
        ├── onReasoning
        │     ├── prepare model input → onSystemPrompt   // 组装 system prompt
        │     └── onModelCall                             // 模型 API 调用
        └── onActing（本轮每个工具调用各一次）

每个钩子的签名是 Flux<AgentEvent> hook(Agent, XxxInput, Function<XxxInput, Flux<AgentEvent>> next)：调用 next.apply(input) 表示继续执行内部逻辑，在此之前/之后插入代码，就形成了“洋葱模型”——多个中间件按 order() 从外到内排列，前半段按正序执行，后半段按逆序执行：

顺序规则// middlewares = [mw1(order=2), mw2(order=1)]
// 执行顺序：
// mw1 前 → mw2 前 → 内部逻辑 → mw2 后 → mw1 后
// order() 越小优先级越高，默认值可覆盖：
MiddlewareBase lowerPriority = new MiddlewareBase() {
    @Override
    public int order() { return 0; }
    // ...
};

7.3 实践：场景一 —— 请求审计日志

RequestContextMiddleware.javaimport io.agentscope.core.agent.Agent;
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.event.AgentEvent;
import io.agentscope.core.middleware.AgentInput;
import io.agentscope.core.middleware.MiddlewareBase;
import java.util.function.Function;
import reactor.core.publisher.Flux;

/** 在最外层记录用户与请求，并且写入 trace id 供工具与后续钩子读取。 */
public class RequestContextMiddleware implements MiddlewareBase {

    @Override
    public Flux<AgentEvent> onAgent(
            Agent agent, RuntimeContext ctx, AgentInput input,
            Function<AgentInput, Flux<AgentEvent>> next) {
        System.out.printf("[req] user=%s session=%s reqId=%s%n",
                ctx.getUserId(), ctx.getSessionId(), ctx.get("request_id"));
        ctx.put("trace_id", java.util.UUID.randomUUID().toString());
        return next.apply(input)
                .doFinally(sig -> System.out.println("[req] done " + sig));
    }
}

注意 ctx.put(...)：写入的是本次调用的瞬态属性层，工具通过 RuntimeContext 类型化属性（第 5 章）就能读到 trace_id，因此一条链路贯穿了中间件与工具。

7.4 实践：场景二 —— 模型调用计时

TimingMiddleware.javaimport io.agentscope.core.agent.Agent;
import io.agentscope.core.event.AgentEvent;
import io.agentscope.core.middleware.MiddlewareBase;
import io.agentscope.core.middleware.ModelCallInput;
import java.util.function.Function;
import reactor.core.publisher.Flux;

public class TimingMiddleware implements MiddlewareBase {

    @Override
    public Flux<AgentEvent> onModelCall(
            Agent agent, ModelCallInput input,
            Function<ModelCallInput, Flux<AgentEvent>> next) {
        long start = System.nanoTime();
        return next.apply(input)
                .doFinally(sig -> {
                    long ms = (System.nanoTime() - start) / 1_000_000;
                    System.out.println("[timing] " + agent.getName() + ": " + ms + "ms");
                });
    }
}

7.7 本章小结

中间件是智能体的横切关注层：六阶段钩子配合洋葱模型，使审计、追踪、过滤与业务完全解耦。核心构件篇到此完成——从下一章开始进入 Harness 篇，智能体将拥有工作区、记忆、技能、子智能体这些“长期运行”的能力。
