14.1 本章场景：从 Demo 到 SaaS

🎬场景任务

客服智能体要交付给 50 家企业客户使用：每家有自己的知识库、技能与配置；部署多副本后，会话状态不能只存在单机内存；凌晨的批量任务不能被交互流量拖垮。因此，本章讨论官方“上生产（Going to Production）”指南的核心内容：分布式状态存储、多租户约定、控制面与数据面分离。

14.2 理论：两块存储，各管一摊

生产部署时，框架的状态分为两块，官方用两个组件分别管理：

组件管什么典型后端
AgentStateStore数据面：会话状态与对话上下文Redis（推荐）、MySQL
DistributedStore控制面：工作区、技能、计划、沙箱快照等长期资产Redis + MySQL + OSS 混合组合

二者分开的原因在于访问模式不同：会话状态读写频繁、生命周期短；工作区资产体积大、变更少。官方提供 RedisDistributedStore（配合 Jedis）与 MysqlDistributedStore（配合数据源）两种实现，一个对象同时提供状态存储与文件基础存储，因此一行配置即可完成装配：

Redis 一键装配import redis.clients.jedis.JedisPooled;

DistributedStore store = RedisDistributedStore.fromJedis(
        new JedisPooled("redis://shared-redis:6379"));

HarnessAgent agent = HarnessAgent.builder()
        .name("cs-agent")
        .model("dashscope:qwen-plus")
        .distributedStore(store)                  // stateStore + baseStore 一键配置
        .filesystem(new RemoteFilesystemSpec()    // 文件走共享存储，多副本可见
                .isolationScope(IsolationScope.USER)
                .workspaceIndex(WorkspaceIndex.open(workspace)))
        .build();

如果偏好环境变量驱动的配置，控制面也可以用 ControlPlaneStores.fromEnv() 装配，再通过 withAgentStateStore(...) 把数据面组合进去：

环境变量装配（示意）ControlPlaneStores cp = ControlPlaneStores.fromEnv();
// ... .distributedStore(cp.withAgentStateStore(redis.agentStateStore()))

14.3 多租户的命名约定

多租户隔离靠键名约定实现：租户、用户、会话按层级编码进存储键。官方给出的约定大致为“租户 → 工作区 → 用户 → 会话”四级；WorkspaceIndex 负责在运行时把租户上下文映射到正确的工作区。实践建议：

  • 租户级配置（模型、技能、工具白名单）放进租户自己的工作区，与第 8 章的覆盖机制天然契合；
  • 不同租户使用不同模型密钥时，用第 3 章的 ModelCreationContext 按请求解析；
  • 技能仓库选 MySQL 版（11.3 节），以租户字段区分，便于运营。

14.4 并发与幂等：会话串行化

同一用户可能同时开两个请求（例如双击发送）。因此框架提供会话串行化执行守护：同一 (userId, sessionId) 的请求自动排队串行执行，避免并发写同一份状态；不同会话之间则完全并行。另外，Redis 状态存储 + 沙箱快照（第 12 章）配合，可以在实例崩溃后把用户“搬”到另一台实例继续对话。

14.5 上线检查清单

✅生产就绪自检
  • 状态存储已切到 Redis/MySQL，且开启持久化；本地 JsonFile 实现仅用于开发；
  • 权限系统按环境配置：无人值守任务使用 DONT_ASK，并叠加 deny 规则；
  • 接入了 OtelTracingMiddleware（第 7 章），日志能按 userId/sessionId 检索；
  • 压缩与记忆共用轻量模型（第 9 章），上下文成本可预估；
  • 不可信代码全部进沙箱，快照存储指向对象存储；
  • 多租户键名约定已评审，租户间无共享可写目录。
✍️动手练习 14
  1. 用 docker-compose 启动 Redis，把状态存储切换过去，验证重启进程后对话仍在；
  2. 并发发送同一 sessionId 的 10 个请求，验证串行化（观察响应顺序）与不同 sessionId 的并行；
  3. 为两个模拟租户准备两份工作区与技能，验证 WorkspaceIndex 的租户隔离。

14.6 本章小结

上生产的关键不是“更多功能”，而是“更清晰的边界”：数据面与控制面分离、租户靠约定隔离、会话靠串行化保一致。所有部件在前 13 章都已出场，本章只是把它们装配成系统。那么，最后一章请你自己完成装配——综合实战项目。
