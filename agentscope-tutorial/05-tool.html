第 5 章工具：让智能体行动

5.1 本章场景：IT 工单查询机器人

🎬场景任务

IT 支持部有一个工单数据库。我们希望员工直接用自然语言询问：“我的上个月的工单处理到哪一步了？”机器人需要调用 query_tickets 工具查询数据库，然后组织成回答。同时，不同员工只能查询自己的工单——因此，本章还要实践“如何把当前用户身份传进工具”。

5.2 理论：工具是模型与真实世界之间的函数

模型只能生成文本，不能查询数据库、不能修改文件。工具（Tool）解决了这个限制：开发者把一个 Java 方法注册到 Toolkit，框架自动把方法签名转换为 JSON Schema 描述交给模型；模型决定“何时调用、传什么参数”，框架负责执行方法并把结果回传给模型继续推理。整个过程对模型而言是一轮“行动”，对开发者而言就是一个普通方法。

AgentScope 提供三种定义工具的方式：@Tool 注解方法（最简单）、ToolBase 子类（需要精细控制权限与异步行为时使用）、MCP 客户端（复用外部工具服务）。此外还有一组内置工具可以直接注册。

5.3 实践：@Tool 注解定义工具

TicketTools.java —— 场景主工具import io.agentscope.core.tool.Tool;
import io.agentscope.core.tool.ToolParam;

public class TicketTools {

    @Tool(
            name = "query_tickets",
            description = "查询当前用户的 IT 工单。可按状态过滤。",
            readOnly = true,          // 只读工具，权限系统可据此放行
            concurrencySafe = true)   // 可并行执行
    public String queryTickets(
            @ToolParam(name = "status", description = "工单状态过滤：OPEN / PROCESSING / CLOSED，可为空")
                    String status,
            UserContext userCtx) {    // ← 类型化属性，框架自动注入，模型看不到
        String owner = (userCtx == null) ? "anonymous" : userCtx.username();
        return ticketDao.findByOwnerAndStatus(owner, status);  // 返回 JSON 字符串
    }
}

// record 定义（第 4 章 RuntimeContext 类型化属性）
public record UserContext(String username, String locale) {}

两个关键点：其一，@ToolParam 的描述会进入模型可见的 Schema，因此描述质量直接影响模型传参的准确性；其二，UserContext 参数不是模型提供的——框架从 RuntimeContext 的类型化属性层自动注入，这样就实现了“模型只管业务，身份由系统决定”的安全边界：

调用时注入身份RuntimeContext ctx =
        RuntimeContext.builder()
                .userId("alice")
                .put(UserContext.class, new UserContext("alice", "zh"))
                .build();

agent.call(List.of(new UserMessage("user", "我上月提的工单处理完了吗？")), ctx).block();

5.4 实践：ToolBase 子类定义工具

需要异步 IO、自定义权限逻辑或流式结果时，继承 ToolBase：

WebSearchTool.java —— 结构完整示例import io.agentscope.core.message.TextBlock;
import io.agentscope.core.message.ToolResultBlock;
import io.agentscope.core.permission.PermissionBehavior;
import io.agentscope.core.permission.PermissionContextState;
import io.agentscope.core.permission.PermissionDecision;
import io.agentscope.core.tool.ToolBase;
import io.agentscope.core.tool.ToolCallParam;
import java.util.List;
import java.util.Map;
import reactor.core.publisher.Mono;

public class WebSearchTool extends ToolBase {

    public WebSearchTool() {
        super(
                ToolBase.builder()
                        .name("WebSearch")
                        .description("Search the web for information on a given query.")
                        .inputSchema(Map.of(
                                "type", "object",
                                "properties", Map.of(
                                        "query", Map.of("type", "string")),
                                "required", List.of("query")))
                        .readOnly(true)
                        .concurrencySafe(true));
    }

    // 细粒度权限：返回 ALLOW / DENY / ASK（ASK 会触发第 6 章的人机确认）
    @Override
    public Mono<PermissionDecision> checkPermissions(
            Map<String, Object> toolInput, PermissionContextState context) {
        return Mono.just(PermissionDecision.allow("Web search is read-only."));
    }

    @Override
    public Mono<ToolResultBlock> callAsync(ToolCallParam param) {
        String query = (String) param.getInput().get("query");
        return doSearchAsync(query)
                .map(text -> ToolResultBlock.builder()
                        .id(param.getId())
                        .name(getName())
                        .output(List.of(TextBlock.builder().text(text).build()))
                        .build());
    }
}

ToolCallParam 还携带 getRuntimeContext()，因此在 ToolBase 内部同样能读到租户与用户身份。

5.5 实践：MCP 客户端与内置工具

AgentScope 支持 Model Context Protocol（MCP），因此庞大的外部工具生态可以直接复用，三种连接方式对应三种部署形态：

三种 MCP 接入// 1. stdio：本地子进程
McpClientWrapper filesystem =
        McpClientBuilder.stdio()
                .name("filesystem")
                .command("mcp-server-filesystem")
                .args("--root", "/my/project")
                .build();

// 2. streamableHttp：远程 HTTP 服务
McpClientWrapper weather =
        McpClientBuilder.streamableHttp()
                .name("weather")
                .url("https://api.weather.com/mcp")
                .header("Authorization", "Bearer xxx")
                .build();

// 3. sse：事件流服务
McpClientWrapper search =
        McpClientBuilder.sse()
                .name("search")
                .url("https://api.search.com/mcp/sse")
                .build();

Toolkit toolkit = new Toolkit();
toolkit.registerMcpClient(filesystem).block();   // 注册是异步的，需要 block 等待

内置工具与工具组：

内置工具与工具组import io.agentscope.core.tool.ToolGroup;
import io.agentscope.core.tool.ToolGroupScope;
import io.agentscope.core.tool.builtin.TodoTools;
import io.agentscope.core.tool.coding.ShellCommandTool;
import io.agentscope.core.tool.file.ReadFileTool;
import io.agentscope.core.tool.file.WriteFileTool;

Toolkit toolkit = new Toolkit();
toolkit.registerTool(new TodoTools());              // 任务列表工具
toolkit.registerTool(new ReadFileTool("/base/dir"));
toolkit.registerTool(new WriteFileTool("/base/dir"));

// 工具组：把高危或低频工具聚合，初始不激活，由模型按需开启
ToolGroup database =
        new ToolGroup("database",
                "Tools for database operations.",
                ToolGroupScope.SESSION,
                /* active = */ false);
database.addTool("db_query");
database.addTool("db_migrate");
toolkit.registerToolGroup(database);

// 配合 enableMetaTool(true)（第 4 章），模型可以自主 list_tools / activate_group
✍️动手练习 5
  1. 为工单机器人再写一个 create_ticket 工具（写操作，readOnly = false），并且观察模型在只读与写工具并存时的选择；
  2. 把 UserContext 注入路径故意断掉（不 put 到 RuntimeContext），运行并观察 userCtx 变为 null 后工具的兜底行为——体会为什么工具内部必须判空；
  3. 接入一个公共 MCP 服务器（例如官方 filesystem server），让它与自定义工具共存。

5.6 本章小结

工具让智能体从“能说”升级为“能做”。三种定义方式（注解、ToolBase、MCP）覆盖从简单到复杂的全部需求，RuntimeContext 注入则保证了身份安全。但是，能做不等于该做——db_migrate 这类工具一旦被模型随意调用后果严重，因此下一章引入权限系统。
