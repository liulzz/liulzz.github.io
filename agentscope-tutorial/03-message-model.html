第 3 章消息、多模态与模型接入

3.1 本章场景：图文报修助手

🎬场景任务

公司行政部想要一个报修机器人：员工上传一张故障设备的照片，并且附带文字说明；机器人识别设备类型与故障现象，输出结构化的工单字段（设备、现象、紧急程度），供工单系统直接消费。这个场景会同时用到多模态消息与结构化输出，并且顺带讲清模型层的三种配置方式。

3.2 理论：消息模型 Msg 与内容块

AgentScope 的所有对话内容都由 Msg 及其子类表达。消息的角色决定能携带什么：

消息类型角色与用途允许的内容块
UserMessage用户输入文本、数据块（图片/音频等多模态）
SystemMessage系统指令仅文本
AssistantMessage模型输出全部类型，含工具调用块

内容块（ContentBlock）是消息的组成单元。常用的有四种：TextBlock（文本）、DataBlock（多模态数据，通过 Base64Source 或 URL 携带）、ToolUseBlock（模型发起的工具调用）、ToolResultBlock（工具返回的结果）。一条消息可以由任意多个块组成，因此“一张图 + 一段文字”在同一条消息里就能表达。

框架同时提供便捷方法：msg.getTextContent() 提取全部文本；msg.getContentBlocks(ToolUseBlock.class) 过滤出指定类型的块。

3.3 实践：构建多模态消息

构造“图片 + 文字”的报修消息import io.agentscope.core.message.Base64Source;
import io.agentscope.core.message.DataBlock;
import io.agentscope.core.message.TextBlock;
import io.agentscope.core.message.UserMessage;

// 方式一：构造函数 + 可变参数块
UserMessage report =
        new UserMessage(
                "user",
                TextBlock.builder().text("打印机坏了，屏幕显示卡纸，但是纸盒里没有纸。").build(),
                DataBlock.builder()
                        .source(Base64Source.builder()
                                .data(base64OfPhoto)          // 图片的 Base64 字符串
                                .mediaType("image/png")
                                .build())
                        .build());

// 方式二：builder 风格，适合纯文本的简单场景
UserMessage simple =
        UserMessage.builder()
                .name("user")
                .textContent("前台空调不制冷")
                .build();

3.4 实践：结构化输出

报修机器人不能只输出一段自由文本，因为工单系统需要程序可读的字段。那么，让模型直接按 Java 类的结构返回即可——call() 提供结构化输出重载，传入一个 POJO 类，框架会生成对应的 JSON Schema 并解析结果：

定义输出结构并调用import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.message.Msg;
import io.agentscope.core.ReActAgent;
import java.util.List;

public class RepairTicket {
    public String device;        // 设备名称
    public String symptom;       // 故障现象
    public String urgency;       // HIGH / MEDIUM / LOW
}

ReActAgent agent = ReActAgent.builder()
        .name("repair-bot")
        .sysPrompt("你是行政报修助手，根据用户的描述输出工单字段。")
        .model("dashscope:qwen-plus")
        .build();

Msg msg = agent.call(
        List.of(report),              // 3.3 中的多模态消息
        RepairTicket.class,           // 指定结构化输出类型
        RuntimeContext.empty())
    .block();

RepairTicket ticket = msg.getStructuredData(RepairTicket.class);
System.out.println(ticket.device + " / " + ticket.urgency);
💡原生结构化输出

部分模型支持原生 json_schema 能力。如果供应商支持，可以在模型构造时开启 .nativeStructuredOutput(true)，解析可靠性更高。但是对于不支持该能力的模型（或开启工具调用时存在兼容问题的场景），框架会自动退回提示词方案，因此两种情况下代码都不需要改动。

3.5 理论与实践：模型层的三种配置方式

第 2 章使用了模型字符串。但是真实项目常常需要更细的控制，因此模型层提供三个层级，按需选用：

方式一：模型字符串（推荐入门）

.model("dashscope:qwen-plus")
// 换供应商只需换字符串：
// "openai:gpt-5.5" / "anthropic:claude-sonnet-4-5"
// "deepseek:deepseek-v4-flash" / "gemini:gemini-2.0-flash" / "ollama:llama3"

底层由 ModelRegistry.resolve(modelId) 解析，并自动读取对应环境变量（DASHSCOPE_API_KEY、OPENAI_API_KEY 等）。

方式二：显式构造 Model 对象

需要指定 base URL、是否流式、默认生成参数时，直接构造模型实例：

显式构造 DashScopeChatModelimport io.agentscope.core.model.GenerateOptions;
import io.agentscope.extensions.model.dashscope.DashScopeChatModel;
import io.agentscope.extensions.model.dashscope.formatter.DashScopeChatFormatter;

DashScopeChatModel model =
        DashScopeChatModel.builder()
                .apiKey(System.getenv("DASHSCOPE_API_KEY"))
                .modelName("qwen-plus")
                .stream(true)
                .formatter(new DashScopeChatFormatter())
                .defaultOptions(
                        GenerateOptions.builder()
                                .temperature(0.2)
                                .parallelToolCalls(false)
                                .build())
                .build();

ReActAgent agent = ReActAgent.builder()
        .name("assistant")
        .model(model)          // 直接传入实例
        .build();

类层级如下，五种内置实现对应五类供应商，OpenAI 实现还能通过 baseUrl 指向任何 OpenAI 兼容服务（例如私有部署模型）：

CredentialBase
└── ChatModelBase
    ├── OpenAIChatModel        （OpenAI 及兼容服务）
    ├── AnthropicChatModel
    ├── DashScopeChatModel
    ├── GeminiChatModel
    └── OllamaChatModel

GenerateOptions 控制采样与推理行为：temperature、top_p、parallelToolCalls，以及思考型模型的 thinkingBudget（配合 .enableThinking(true) 使用）。

方式三：Spring Boot starter（推荐企业项目）

pom.xml<dependency>
    <groupId>io.agentscope</groupId>
    <artifactId>agentscope-dashscope-spring-boot-starter</artifactId>
    <version>${agentscope.version}</version>
</dependency>

starter 按约定自动装配 Model Bean（密钥等从环境变量读取），因此无需手写模型配置；进一步可以通过 Customizer Bean 在启动时统一调整参数：

全局默认生成参数@Configuration(proxyBeanMethods = false)
class ModelCustomizerConfiguration {

    @Bean
    @Order(0)
    OpenAIChatModelBuilderCustomizer openAIModelDefaults() {
        return builder ->
                builder.defaultOptions(
                        GenerateOptions.builder()
                                .temperature(0.2)
                                .parallelToolCalls(false)
                                .build());
    }
}

进阶：多租户按请求选模型

如果不同租户要使用不同的模型或密钥，可以使用 ModelCreationContext：把 apiKey、baseUrl、扩展选项与组件对象组装为一个上下文，再交给 ModelRegistry 在运行时创建模型实例。这样，一套代码就能服务多个租户，细节将在第 14 章的生产篇展开。

✍️动手练习 3
  1. 给 RepairTicket 增加两个字段：estimatedMinutes（预计处理时长）与 needsOnsite（是否需要上门），并且重新运行，观察模型是否遵循新结构；
  2. 把报修机器人改为显式构造模型，并且设置 temperature(0.1)；对比输出稳定性；
  3. （可选）用 streamEvents() 在结构化输出调用前先输出一句“正在生成工单……”，体验事件流与结构化调用的组合。

3.6 本章小结

消息模型是“角色 + 内容块”的组合，因此多模态输入只需拼装 DataBlock；结构化输出让模型结果可以直接映射到 Java 类。模型层提供字符串寻址、显式构造、Spring starter 三个层级，那么你可以按项目复杂度逐步升级配置方式。下一章我们回到 ReActAgent 本体，把它的完整接口讲透。
