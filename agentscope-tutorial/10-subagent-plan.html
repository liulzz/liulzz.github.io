第 10 章子智能体与计划模式

10.1 本章场景：代码评审流水线

🎬场景任务

主智能体收到一句模糊的指令：“把这个仓库整理得更好。”直接执行既危险又低效。正确做法是：先进入计划模式把工作拆解成步骤并与用户对齐，再把“代码评审”这样的专业环节委派给子智能体。因此，本章引入 Harness 的两个协作特性：子智能体（Subagent）与计划模式（Plan Mode）。

10.2 理论：子智能体是“可以委派的同事”

子智能体是拥有独立上下文、独立工具集、（可选）独立工作区的完整智能体。主智能体通过两个内置工具与它们协作：

  • agent_spawn：创建并启动一个子智能体执行任务；
  • agent_send：向运行中的子智能体追加消息或追问结果。

与“把所有事塞进一个大提示词”相比，委派模式的优势在于上下文隔离：子智能体产生的中间输出不会占据主智能体的上下文窗口，因此主智能体始终保留全局视野。子智能体有两种声明方式：

  1. 声明式（推荐）：在工作区 subagents/ 目录放置 Markdown 文件，文件名即 agent_id；
  2. 编程式：用 SubagentDeclaration.builder() 构建对象，适合动态生成；远程子智能体还可以通过 url 指向独立部署的服务。

10.3 实践：声明一个评审子智能体

.agentscope/workspace/subagents/code-reviewer.md---
description: 代码评审专家。当用户需要 review 代码、检查风格或审查 PR 时使用。
model: dashscope:qwen-plus       # 可选；不写则继承主智能体
steps: 8                          # 可选；单次任务最大推理-行动轮数
temperature: 0.2                  # 可选；覆盖默认生成参数
hidden: false                     # true 时模型不可见（只能程序化 spawn）
expose_to_user: true              # 可选；控制是否在用户界面展示
tools:                            # 可选；继承工具的白名单
  - read_file
  - grep_files
---

你是专注代码评审的子智能体。请按以下流程工作：
1. 先使用 read_file / grep_files 收集上下文
2. 按文件与行号给出具体建议
3. 末尾给出 1-5 的总体评分

声明完成后无需注册代码——HarnessAgent 构建时自动扫描 subagents/ 目录，并且把可用子智能体的名称与 description 注入主智能体上下文，由模型自主决定何时委派。运行时对话里就会出现类似这样的工具调用：

模型自动发起的委派agent_spawn agent_id="code-reviewer" task="评审 utils/ 目录下的全部改动"

10.4 子智能体的会话与隔离

子智能体同样拥有会话持久化：它的运行日志保存在 .agentscope/workspace/agents/<agentId>/sessions/ 下，因此“上一次评审到哪一步”可以被恢复与审计。工作区隔离模式（workspace 声明项）则决定子智能体是共享主工作区还是使用独立目录——涉及文件写入的任务建议隔离。

10.5 理论：计划模式

计划模式让智能体在“动手”之前先“立字据”：进入该模式后，框架提供 plan_enter / plan_write / plan_exit 与 todo_write 等计划工具，智能体把拆解好的步骤写入 plans/ 目录下的计划文件，与用户对齐后再切换到执行状态。它的价值在于：

  • 复杂任务先对齐方案，减少返工与误操作；
  • 计划即审计材料——每个任务的状态（待办、进行中、完成）都有据可查；
  • 可与权限系统联动：计划评审通过后，才放行写操作权限。

10.6 实践：开启计划模式

构建时开启import java.nio.file.Paths;

HarnessAgent agent = HarnessAgent.builder()
        .name("repo-steward")
        .model("dashscope:qwen-plus")
        .workspace(Paths.get(".agentscope/workspace"))
        .planFileDirectory("plans")
        .enablePlanMode(true)
        .build();
运行时控制（管理接口）// 需要用户先看方案时，程序也可以主动进入/退出计划模式
agent.enterPlanMode(ctx);
// agent.isPlanModeActive(ctx)  → true
agent.exitPlanMode(ctx);
✍️动手练习 10
  1. 为 10.3 的评审子智能体增加 tools 白名单以外的工具，观察声明是否把它从模型可见列表中排除；
  2. 开启计划模式后输入“帮我整理这个仓库”，查看 plans/ 目录生成的计划文件，并且验证 todo_write 更新任务状态；
  3. 再声明一个 hidden: true 的子智能体，验证模型无法自主 spawn 它，但是通过程序仍然可以调用。

10.7 本章小结

子智能体把“专业环节”封装为可委派、可隔离、可审计的单元；计划模式把“先对齐再执行”固化为产品能力。两者结合，智能体开始具备团队协作的雏形。但是评审者凭什么懂你们团队的规范？下一章用技能系统解决这个问题。
