第 2 章环境搭建与第一个智能体

2.1 本章场景：会议准备助理

🎬场景任务

天宇明天要做一场关于 ReAct 的技术分享，但是准备工作千头万绪。因此，我们要构建一个助理 note-taker：它记住用户告诉它的信息，回答关于准备事项的追问，并且能够流式输出长回答。这个场景虽小，但是覆盖了智能体应用的三个基本要素：模型调用、会话状态、流式响应。

2.2 理论：最小可用智能体的构成

第 1 章提到，智能体 = 模型 + 工具 + 行为准则。本章先不引入工具，因此最小智能体只需要三步：引入依赖、提供模型密钥、构建 Agent 实例。其中有一个关键设计需要先理解——模型字符串。

AgentScope 使用 "厂商:模型名" 格式的字符串来寻址模型，例如 "dashscope:qwen-plus"。框架内部的 ModelRegistry 会解析这个字符串，并且自动读取对应的环境变量（如 DASHSCOPE_API_KEY）。因此，切换供应商时不需要改动 Java 代码，只需要更换字符串与密钥。

2.3 实践：创建项目

步骤 1：初始化 Maven 项目并添加依赖

pom.xml（关键部分）<properties>
    <maven.compiler.source>17</maven.compiler.source>
    <maven.compiler.target>17</maven.compiler.target>
    <agentscope.version>2.0.3</agentscope.version>
</properties>

<dependencies>
    <!-- 智能体核心（含 HarnessAgent / ReActAgent） -->
    <dependency>
        <groupId>io.agentscope</groupId>
        <artifactId>agentscope-harness</artifactId>
        <version>${agentscope.version}</version>
    </dependency>
    <!-- DashScope（通义千问）模型扩展 -->
    <dependency>
        <groupId>io.agentscope</groupId>
        <artifactId>agentscope-extensions-model-dashscope</artifactId>
        <version>${agentscope.version}</version>
    </dependency>
</dependencies>

步骤 2：配置模型密钥

终端export DASHSCOPE_API_KEY="sk-你的密钥"

如果你使用 OpenAI 兼容服务，那么改用 openai: 前缀并设置 OPENAI_API_KEY 与自定义 base URL 即可（详见第 3 章）。

步骤 3：编写第一个智能体

src/main/java/com/example/FirstAgent.javaimport io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.message.UserMessage;
import io.agentscope.harness.agent.HarnessAgent;

import java.nio.file.Paths;

public class FirstAgent {
    public static void main(String[] args) {
        HarnessAgent agent = HarnessAgent.builder()
                .name("note-taker")
                .sysPrompt("你是天宇的会议准备助理，帮助他整理 ReAct 技术分享的要点。")
                // 模型字符串由 ModelRegistry 解析，自动读取 DASHSCOPE_API_KEY
                .model("dashscope:qwen-plus")
                // 工作区目录：状态、记忆、会话日志都存放在这里
                .workspace(Paths.get(".agentscope/workspace"))
                // 上下文压缩：超过 30 条消息时触发，保留最近 10 条
                .compaction(CompactionConfig.builder()
                        .triggerMessages(30)
                        .keepMessages(10)
                        .build())
                .build();

        RuntimeContext ctx = RuntimeContext.builder()
                .sessionId("demo-session")
                .userId("tianyu")
                .build();

        // 第一轮：告诉助理两件事
        agent.call(new UserMessage("我叫天宇，今天准备一个关于 ReAct 的技术分享。"), ctx).block();

        // 第二轮：同一个 sessionId，助理自动恢复上一轮的状态
        agent.call(new UserMessage("我叫什么？我今天要干什么？"), ctx).block();
    }
}

运行后，第二轮回答会包含“天宇”和“ReAct 技术分享”。也就是说，跨请求的状态恢复已经自动完成——这正是 AgentState 在起作用（原理见第 4 章）。

2.4 实践：流式输出

call() 会等待完整回答。但是用户界面通常需要“边生成边显示”，因此框架提供 streamEvents()：它返回一个事件流，每个事件是一个 AgentEvent 对象。

流式消费事件agent.streamEvents(new UserMessage("user", "帮我把今天的关键点列三条。"), ctx)
    .doOnNext(event -> {
        if (event instanceof TextBlockDeltaEvent delta) {
            // 只输出文本增量，即可实现打字机效果
            System.out.print(delta.getDelta());
        }
    })
    .blockLast();

事件类型不止文本增量一种：工具调用的开始与结束、需要用户确认的请求等都有对应事件。第 4 章会给出完整的事件类型清单。

2.5 观察：工作区里发生了什么

运行结束后，查看 .agentscope/workspace/ 目录：

.agentscope/workspace/
├── AGENTS.md                 # 智能体人格文件（可选，手写后自动生效）
└── agents/note-taker/
    └── sessions/             # 每个会话一份 JSONL 日志，永不压缩

两个要点值得注意。其一，AGENTS.md 是 HarnessAgent 的工作区人格文件——把行为准则写在这里，比把长提示词堆在代码里更易维护（第 8 章展开）。其二，sessions/ 保存原始对话日志，压缩只影响进入模型上下文的内容，不会破坏日志，因此随时可以审计历史。

✍️动手练习 2

在 2.3 代码的基础上完成三个改动：

  1. 把 sessionId 改为 "session-b" 再运行，观察助理是否还记得“天宇”——思考为什么；
  2. 修改 sysPrompt，让助理在每次回答末尾附加一条备会建议；
  3. 把 .model("dashscope:qwen-plus") 换成你能访问的其他模型字符串，验证模型无关性。

验证标准：第 1 项中助理应当表示不知道，因为不同 sessionId 对应不同会话状态。

2.6 本章小结

本章用不到 40 行 Java 代码构建了一个具备会话记忆与流式输出能力的助理。你已经接触了五个核心 API：HarnessAgent.builder()、.model()、RuntimeContext、call()、streamEvents()。下一章我们深入消息模型与模型层，理解多模态输入与多厂商切换的完整机制。
