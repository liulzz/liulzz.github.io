第 11 章技能系统

11.1 本章场景：把团队规范交给智能体

🎬场景任务

团队有一份 40 页的《代码评审规范》，并且规范每季度更新。第 10 章的评审子智能体需要“懂”这份规范，但是把全文塞进 system prompt 既浪费上下文，更新也不及时。因此，本章使用技能（Skill）：以 Markdown 文件承载领域知识，让模型按需加载，并且支持从 Git 仓库、注册中心等来源热更新。

11.2 理论：技能 = 指令 + 参考资料 + 脚本

一个技能是一个目录，核心是 SKILL.md：

技能目录结构code-reviewer/
├── SKILL.md           # 必需：YAML frontmatter（name + description）+ 给模型看的指令
├── references/        # 可选：长篇参考资料，模型按需读取
│   └── style-guide.md
└── scripts/           # 可选：模型可通过 shell 执行的脚本
    └── run-checks.sh
SKILL.md 示例---
name: code-reviewer
description: 当用户需要代码评审、风格反馈或 PR 审核时使用。
---

# Code Reviewer

步骤：
1. 读 references/style-guide.md 获取项目规范
2. 执行 scripts/run-checks.sh <目标路径>，把结果汇总给用户

两个设计要点值得注意。其一，description 是模型选择技能的依据，因此要用“什么场景下使用”的句式来写；其二，技能是渐进加载的——默认只有 name 与 description 进入上下文，正文与参考资料在模型决定使用时才读取，所以技能数量多也不会撑爆上下文。

11.3 实践：技能的四种来源

AgentScope 把技能的存储抽象为 SkillRepository，同一个智能体可以同时挂载多个来源：

1. 类路径 —— 适合随应用打包的内置技能HarnessAgent.builder()
        .skillRepository(new ClasspathSkillRepository("skills"))
        .build();
2. Git 仓库 —— 团队技能库，拉取即更新HarnessAgent.builder()
        .skillRepository(
            new GitSkillRepository("https://github.com/your-org/team-skills.git"))
        .build();
3. Nacos —— 配置中心托管，运行时可热更新HarnessAgent.builder()
        .skillRepository(nacosSkillRepository)
        .build();
4. MySQL —— 数据库存储，支持多租户读写MysqlSkillRepository registry = MysqlSkillRepository.builder(dataSource)
        .databaseName("agentscope")
        .skillsTableName("skills")
        .createIfNotExist(true)
        .writeable(true)
        .build();

HarnessAgent.builder()
        .skillRepository(registry)
        .build();

多个来源可以叠加，同名技能按声明顺序决定优先级：

多来源叠加HarnessAgent.builder()
        .skillRepository(communityMarket)   // 社区技能
        .skillRepository(internalRegistry)  // 公司注册中心
        .skillRepository(teamGitRepo)       // 团队 Git 仓库
        .build();

11.4 工作区技能目录

除了代码声明的来源，工作区的 skills/ 目录始终生效（见第 8 章），并且支持用户级覆盖——结合 8.6 节的两级解析，个人可以定制自己的技能版本：

工作区技能workspace/skills/
└── code-reviewer/
    ├── SKILL.md
    ├── references/
    │   └── style-guide.md
    └── scripts/
        └── run-checks.sh

那么，“技能”与“工具”如何选择？经验法则是：工具是“能力”（需要代码执行、有确定输入输出）；技能是“知识”（需要人维护、以文本为主）。评审规范属于后者，因此做成技能；查数据库属于前者，做成工具。

✍️动手练习 11
  1. 把你们团队（或自拟）的规范写成一个技能，放到工作区 skills/，验证模型在评审请求时自动引用它；
  2. 把技能正文故意写得与 description 矛盾，观察模型行为——体会 description 的重要性；
  3. 给技能增加 scripts/ 与 references/，验证模型会按需读取而非一次性载入。

11.5 本章小结

技能用“Markdown + 渐进加载”把易变的知识与稳定的代码分离，四种仓库来源覆盖从内置打包到多租户运营的完整谱系。至此，智能体的“内功”齐了；但是让它自主执行脚本前，还差最后一块安全拼图——下一章：文件系统与沙箱。
