一、什么是 GitHub Pages

GitHub Pages 是 GitHub 提供的免费静态网站托管服务。你只需要把 HTML/CSS/JS 文件推送到 GitHub 仓库，GitHub 就会自动帮你把它们变成一个可以访问的网站。

核心特性

特性说明
💰 完全免费Public 仓库免费，Pro 用户 Private 仓库也可用
🌐 自带域名用户名.github.io/仓库名
🔒 HTTPS自动配置 SSL 证书
🔄 自动部署Push 代码即自动更新网站
📦 支持自定义域名可以绑定你自己的域名
⚡ 全球 CDN通过 Fastly CDN 加速访问

使用限制

限制项上限
仓库大小建议 < 1 GB
网站大小< 1 GB
带宽100 GB / 月
构建次数10 次 / 小时

二、5 分钟极速上手（纯网页操作）

不需要安装任何工具，全程在浏览器里完成。

1

创建 GitHub 仓库

打开 github.com/new，填写：

  • Repository name：my-website（或任意名字）
  • 选择 Public
  • 勾选 Add a README file
  • 点击 Create repository
↓
2

上传你的网页文件

在仓库页面点击 Add file → Create new file：

  • 文件名输入 index.html
  • 粘贴以下内容：
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <title>我的第一个 GitHub Pages 网站</title>
  <style>
    body { font-family: sans-serif; text-align: center; padding: 50px; }
    h1 { color: #58a6ff; }
  </style>
</head>
<body>
  <h1>🎉 Hello, GitHub Pages!</h1>
  <p>这是我的第一个静态网站</p>
</body>
</html>

点击 Commit changes 保存。

↓
3

开启 GitHub Pages

  1. 进入仓库 → Settings（设置）
  2. 左侧菜单找到 Pages
  3. Source 选择 Deploy from a branch
  4. Branch 选择 main，目录选 / (root)
  5. 点击 Save
↓
4

访问你的网站 🎉

等待 1-2 分钟后，访问：

https://你的用户名.github.io/my-website/
如果显示 404，等几分钟再刷新。首次部署需要时间。

三、用 gh CLI 部署（命令行玩家）

如果你更喜欢终端操作，用 gh CLI 可以一行命令搞定。

前置准备

# 安装 gh CLI（如果还没装）
brew install gh          # macOS
sudo apt install gh      # Ubuntu/Debian

# 登录 GitHub
gh auth login

一键部署

# 1. 创建项目目录并写入网页
mkdir my-site && cd my-site
echo '<h1>Hello Pages!</h1>' > index.html

# 2. 初始化 Git
git init && git add . && git commit -m "init"

# 3. 创建 GitHub 仓库并推送（自动创建公开仓库）
gh repo create my-site --public --source=. --push

# 4. 开启 GitHub Pages
gh api repos/{owner}/my-site/pages -X POST --input - <<'EOF'
{"source":{"branch":"main","path":"/"}}
EOF
关键点：gh repo create 加 --push 会自动推送代码，省去手动设置 remote 的步骤。

常用 gh pages 命令

# 查看 Pages 状态
gh api repos/{owner}/{repo}/pages

# 修改 Pages 源分支
gh api repos/{owner}/{repo}/pages -X PUT --input - <<'EOF'
{"source":{"branch":"main","path":"/"}}
EOF

# 关闭 Pages
gh api repos/{owner}/{repo}/pages -X DELETE

四、自定义域名配置

步骤

  1. 在域名服务商处添加 CNAME 记录： 
    类型: CNAME
主机记录: www（或 @）
记录值: 你的用户名.github.io
  2. 在仓库根目录创建 CNAME 文件，内容为你的域名： 
    www.example.com
  3. 进入 Settings → Pages → Custom domain，填入你的域名
  4. 勾选 Enforce HTTPS（等证书签发后）
DNS 解析生效需要几分钟到几小时不等。GitHub 会自动申请 Let's Encrypt SSL 证书。

APEX 域名（裸域名）配置

如果用 example.com（不带 www），需要添加 4 条 A 记录：

185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153

五、Jekyll 静态博客

GitHub Pages 原生支持 Jekyll，可以用 Markdown 写博客。

快速开始

# 安装 Jekyll
gem install jekyll bundler

# 创建博客
jekyll new my-blog && cd my-blog

# 本地预览
bundle exec jekyll serve
# 访问 http://localhost:4000

# 推送到 GitHub
git init && git add . && git commit -m "init"
gh repo create my-blog --public --source=. --push

目录结构

my-blog/
├── _posts/           # 博客文章（Markdown）
│   └── 2026-05-20-hello-world.md
├── _config.yml       # Jekyll 配置
├── index.html        # 首页模板
└── Gemfile           # Ruby 依赖

写一篇文章

# _posts/2026-05-20-hello-world.md
---
layout: post
title: "Hello World"
date: 2026-05-20
categories: [博客]
---

这是我的第一篇博客文章。

GitHub Pages + Jekyll = 免费博客 ✨
推荐主题：GitHub 官方主题、Minimal Mistakes、Academic Pages

六、GitHub Actions 自动部署

对于非 Jekyll 项目（如 Vite、Next.js 导出的静态文件），需要用 Actions 自动构建和部署。

通用模板

# .github/workflows/deploy.yml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: true

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install & Build
        run: |
          npm ci
          npm run build    # 输出到 dist/ 目录

      - name: Deploy to Pages
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./dist

      - name: Deploy
        uses: actions/deploy-pages@v4

设置

Settings → Pages → Source 改为 GitHub Actions（而不是 Deploy from a branch）。

注意：使用 Actions 部署时，Source 必须选 "GitHub Actions"，不能选 "Deploy from a branch"，两者互斥。

七、SPA 应用部署（React/Vue）

React (Vite)

# vite.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  base: '/my-repo-name/',   // ⚠️ 必须设置，否则资源路径 404
})

Vue (Vite)

# vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  base: '/my-repo-name/',
})

SPA 路由 404 问题

SPA 用前端路由（如 React Router），直接访问子路由会 404。解决方案：

# 在 public/ 目录下创建 404.html，内容重定向到 index.html
<script>
  sessionStorage.redirect = location.href;
</script>
<meta http-equiv="refresh" content="0;URL='/'">
# 在 index.html 的 <head> 中添加
<script>
  (function() {
    var redirect = sessionStorage.redirect;
    delete sessionStorage.redirect;
    if (redirect && redirect != location.href) {
      history.replaceState(null, null, redirect);
    }
  })();
</script>

八、踩坑大全

🕳️ 坑 1：分支名 master vs main

GitHub Pages 默认查找 main 分支。如果你的本地默认分支是 master，部署后会 404。
# 解决：重命名分支
git branch -m master main
git push origin main

# 如果远程已有 master，需要修改默认分支
gh api repos/{owner}/{repo} -X PATCH -f default_branch=main

🕳️ 坑 2：base 路径问题

仓库名为 my-site 时，网站路径是 用户名.github.io/my-site/。所有资源路径必须包含 /my-site/ 前缀。
# ❌ 错误：资源 404
<link href="/style.css">
<img src="/logo.png">

# ✅ 正确：加上仓库名前缀
<link href="/my-site/style.css">
<img src="/my-site/logo.png">

🕳️ 坑 3：大小写敏感

GitHub Pages 的文件名区分大小写（即使你本地 macOS/Windows 不区分）。

# ❌ 本地能访问，部署后 404
<img src="Photo.JPG">   # 实际文件名是 photo.jpg

🕳️ 坑 4：Jekyll 忽略下划线开头的文件

Jekyll 会忽略 _ 开头的目录（如 _assets/、_components/）。

# 解决：在根目录创建 .nojekyll 文件
touch .nojekyll
git add .nojekyll && git commit -m "disable jekyll"
React/Vue 等框架构建出的文件通常含 _ 前缀（如 _app/），必须添加 .nojekyll。

🕳️ 坑 5：Pages 部署来源冲突

Settings → Pages 的 Source 有两种模式：

模式适用场景
Deploy from a branch直接部署分支中的静态文件（含 Jekyll 构建）
GitHub Actions自定义构建流程（Vite/Webpack/Next.js 等）

两种模式互斥，切换后之前的配置会失效。

🕳️ 坑 6：404 页面

GitHub Pages 支持自定义 404 页面：在根目录放一个 404.html 文件即可。

九、常见问题

❓ Private 仓库能用 GitHub Pages 吗？

可以，但需要 GitHub Pro（$4/月）。Free 用户只能用 Public 仓库。

❓ 支持后端/API 吗？

不支持。GitHub Pages 只能托管静态文件。需要后端请用 Vercel、Netlify、Cloudflare Pages 等。

❓ 支持 HTTPS 吗？

支持，自动配置。自定义域名也会自动申请 Let's Encrypt 证书。

❓ 部署后多久生效？

首次部署 1-5 分钟，后续更新通常 1 分钟内。

❓ 怎么查看部署状态？

仓库 → Actions 标签页查看构建状态。或者 gh run list。

❓ 能用 Vue/React/Angular 吗？

能。需要先构建为静态文件（npm run build），然后用 GitHub Actions 部署 dist/ 目录。
