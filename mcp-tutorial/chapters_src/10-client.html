第 10 章：自己写一个 MCP Client

10.1 为什么要理解 Client 侧

前面的章节都是从 Server 视角展开的。但是，如果你要把 MCP 集成进自己的 AI 应用（而不是使用 Claude Desktop 这类现成 Host），就必须实现 Client 侧逻辑。理解 Client 侧，也有助于理解整个协议的闭环。

Client 的核心职责有三个：

  1. 与 Server 建立连接并完成握手。
  2. 把 Server 的 Tool 列表转换为 LLM 所需的 Function Calling 格式。
  3. 驱动「LLM 决策 → 调用 Tool → 回填结果 → 再次请求 LLM」的循环。

10.2 Client 骨架

# mcp_client.py
import asyncio
from contextlib import AsyncExitStack
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client


class MCPClient:
    def __init__(self):
        self.session: ClientSession | None = None
        self.exit_stack = AsyncExitStack()

    async def connect_stdio(self, command: str, args: list[str]):
        """通过 stdio 连接到一个 MCP Server。"""
        params = StdioServerParameters(command=command, args=args)
        read, write = await self.exit_stack.enter_async_context(
            stdio_client(params)
        )
        self.session = await self.exit_stack.enter_async_context(
            ClientSession(read, write)
        )
        await self.session.initialize()

        tools = await self.session.list_tools()
        print(f"已连接，可用 Tool：{[t.name for t in tools.tools]}")

    async def close(self):
        await self.exit_stack.aclose()

10.3 与 LLM 的调用循环

Client 需要把 MCP 的 Tool 格式转换为 LLM 的 Tool 格式。下面以 Anthropic Messages API 为例。

    def _to_anthropic_tools(self, mcp_tools) -> list[dict]:
        """把 MCP Tool 转换为 Anthropic tools 格式。"""
        return [
            {
                "name": t.name,
                "description": t.description or "",
                "input_schema": t.inputSchema,
            }
            for t in mcp_tools
        ]

核心的调用循环逻辑：模型可能连续多次调用 Tool，因此需要一个循环，直到模型不再请求调用为止。

    async def chat(self, user_message: str, anthropic_client) -> str:
        """处理一轮用户消息，含多次 Tool 调用。"""
        tools_resp = await self.session.list_tools()
        anthropic_tools = self._to_anthropic_tools(tools_resp.tools)

        messages = [{"role": "user", "content": user_message}]

        while True:
            resp = anthropic_client.messages.create(
                model="[REDACTED]",
                max_tokens=1024,
                tools=anthropic_tools,
                messages=messages,
            )

            # 模型不再请求调用 Tool，结束循环
            if resp.stop_reason != "tool_use":
                return "".join(
                    b.text for b in resp.content if b.type == "text"
                )

            messages.append({"role": "assistant", "content": resp.content})

            # 逐个执行模型请求的 Tool 调用
            tool_results = []
            for block in resp.content:
                if block.type == "tool_use":
                    result = await self.session.call_tool(
                        block.name, block.input
                    )
                    tool_results.append({
                        "type": "tool_result",
                        "tool_use_id": block.id,
                        "content": result.content[0].text,
                    })

            messages.append({"role": "user", "content": tool_results})

10.4 完整可运行示例

# main.py
import asyncio
import anthropic
from mcp_client import MCPClient


async def main():
    client = MCPClient()
    # 连接到第 3 章写的 server.py
    await client.connect_stdio("python", ["server.py"])

    anthropic_client = anthropic.Anthropic()  # 读取 ANTHROPIC_API_KEY 环境变量

    try:
        answer = await client.chat("帮我计算 128 加 256 等于多少", anthropic_client)
        print("模型回复：", answer)
    finally:
        await client.close()


if __name__ == "__main__":
    asyncio.run(main())

运行后，内部发生的完整流程：

  1. Client 连接 Server，获取 add 等 Tool。
  2. 把用户消息和 Tool 列表发给 LLM。
  3. LLM 决定调用 add(a=128, b=256)，返回 tool_use。
  4. Client 执行 tools/call，Server 返回 384。
  5. Client 把结果回填，再次请求 LLM。
  6. LLM 生成最终自然语言回复：「128 加 256 等于 384」。

10.5 实现要点

生产级 Client 需要额外考虑

1. 并发调用：模型可能在一轮里请求多个 Tool，可用 asyncio.gather 并发执行以降低延迟。

2. 错误回填：Tool 执行失败时，应把错误信息作为 tool_result 回填给模型（并标记 is_error），因此模型可以据此调整策略。

3. 超时控制：为每次 tools/call 设置超时，避免单个 Tool 卡住整个对话。

4. Tool 名称冲突：连接多个 Server 时，不同 Server 可能有同名 Tool，需要加前缀区分（如 db__query、fs__query）。

✓ 本章小结

Client 的本质是一个「翻译器 + 调度器」：它把 MCP Tool 翻译为 LLM 的 Tool 格式，并驱动多轮调用循环。理解了这个循环，就理解了 MCP 在实际 AI 应用中如何运转。下一章讨论 MCP 中最容易被忽视但最重要的安全问题。
