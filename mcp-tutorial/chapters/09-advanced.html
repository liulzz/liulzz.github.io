第 9 章：进阶特性

9.1 Sampling：Server 反向调用 LLM

普通场景下，Client 调用 Server 上的 Tool。但有些 Server 自身需要 LLM 能力（例如一个「代码审查 Server」需要 LLM 来分析代码），因此 MCP 提供了 Sampling 机制：Server 可以向 Client 发送 sampling/createMessage 请求，由 Client 代为调用 LLM。

这个设计的关键点在于：模型凭证始终保留在 Client 侧，Server 永远无法获取 API Key，因此安全边界清晰。

from mcp.server.fastmcp import FastMCP, Context

mcp = FastMCP("code-review-server")


@mcp.tool()
async def review_code(code: str, ctx: Context) -> str:
    """用 LLM 审查代码，分析潜在问题。"""
    # Server 向 Client 请求 LLM 补全
    response = await ctx.sample(
        messages=[
            {
                "role": "user",
                "content": {
                    "type": "text",
                    "text": f"请分析以下代码的潜在 bug 和改进点：\n\n{code}",
                },
            }
        ],
        max_tokens=500,
        system_prompt="你是一位专业的代码审查工程师，给出简洁、具体的意见。",
    )
    return response.content.text

Client 侧发生的事情：当 Server 发来 sampling/createMessage 时，Host 会在显示界面弹出确认（或静默处理），把请求转发给实际的 LLM，再把 LLM 的回复返回给 Server。

对应的 JSON-RPC 报文：

// Server → Client
{ "jsonrpc": "2.0", "id": 20, "method": "sampling/createMessage",
  "params": {
    "messages": [{ "role": "user", "content": { "type": "text", "text": "..." } }],
    "maxTokens": 500,
    "systemPrompt": "你是一位专业的代码审查工程师..."
  } }

// Client → Server（LLM 返回后）
{ "jsonrpc": "2.0", "id": 20, "result": {
    "role": "assistant",
    "content": { "type": "text", "text": "发现以下问题：..." },
    "model": "[REDACTED]",
    "stopReason": "end_turn"
} }
⚠ 人在环路原则

MCP 规范强调，在 Sampling 调用前，Host 应向用户呈现请求内容并获得确认（或提供拒绝的途径）。不加验证地让 Server 自动调用 LLM 会带来安全风险：一个恶意 Server 可能通过 Sampling 引导 LLM 产生有害内容。

9.2 Elicitation：向用户追问

Elicitation（询唤）允许 Server 在处理请求的过程中，向用户追问所需的额外信息，而不必中断整个工具调用。这对于那些需要运行时输入（如确认、选择、补全参数）的 Server 非常有用。

@mcp.tool()
async def delete_files(pattern: str, ctx: Context) -> str:
    """按模式删除文件，删除前向用户确认。"""
    import glob
    matched = glob.glob(pattern)
    if not matched:
        return "没有匹配的文件。"

    # 向用户询问确认
    result = await ctx.elicit(
        message=f"即将删除以下 {len(matched)} 个文件：\n"
                + "\n".join(matched[:10])
                + ("\n…" if len(matched) > 10 else "")
                + "\n\n是否确认？",
        schema={
            "type": "object",
            "properties": {
                "confirm": {
                    "type": "boolean",
                    "title": "确认删除",
                    "description": "选择 true 确认，false 取消",
                }
            },
            "required": ["confirm"],
        },
    )

    if result.action == "cancel" or not result.data.get("confirm"):
        return "操作已取消。"

    for f in matched:
        import os; os.remove(f)
    return f"已删除 {len(matched)} 个文件。"

9.3 Roots：声明文件系统访问范围

Roots 允许 Client 告知 Server 它被授权访问的文件系统根目录列表。Server 据此知道自己可以安全地访问哪些路径，而不必依赖 Server 自己的猜测。

# Client 侧：声明 roots 能力
# 在 initialize 时 Client 声明 capabilities.roots
# Server 通过 roots/list 反向请求 Client 返回当前根目录

# Server 侧：查询 roots
@mcp.tool()
async def list_workspace_files(ctx: Context) -> str:
    """列出当前工作区下的文件（仅限 roots 声明的范围）。"""
    roots = await ctx.get_roots()  # 调用 roots/list
    result = []
    import os
    for root in roots:
        if root.uri.startswith("file://"):
            path = root.uri[7:]
            for entry in os.scandir(path):
                result.append(f"{root.name}: {entry.name}")
    return "\n".join(result) if result else "未找到任何文件。"

Roots 的实际 JSON-RPC 交互：

// Server → Client
{ "jsonrpc": "2.0", "id": 30, "method": "roots/list" }

// Client → Server
{ "jsonrpc": "2.0", "id": 30, "result": {
    "roots": [
      { "uri": "file:///home/user/project", "name": "my-project" },
      { "uri": "file:///home/user/notes", "name": "notes" }
    ]
} }

9.4 多 Server 组合模式

实际场景中，一个 Host 会同时连接多个 Server。因此，模型可以在同一次对话中，先调用数据库 Server 查询数据，再调用邮件 Server 发送结果。

import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client


async def run_multi_server():
    db_params = StdioServerParameters(command="python", args=["db_server.py"])
    email_params = StdioServerParameters(command="python", args=["email_server.py"])

    async with stdio_client(db_params) as (r1, w1), \
               stdio_client(email_params) as (r2, w2):
        async with ClientSession(r1, w1) as db_session, \
                   ClientSession(r2, w2) as email_session:

            await asyncio.gather(
                db_session.initialize(),
                email_session.initialize(),
            )

            # 合并两个 Server 的 Tool 列表，一并传给 LLM
            db_tools = await db_session.list_tools()
            email_tools = await email_session.list_tools()
            all_tools = db_tools.tools + email_tools.tools
            print(f"共加载 {len(all_tools)} 个 Tool")

asyncio.run(run_multi_server())
✓ 本章小结

三个进阶特性各有侧重：Sampling 让 Server 可以借用 LLM 能力而不持有凭证；Elicitation 让 Server 在运行时向用户追问；Roots 让 Client 向 Server 声明授权访问范围。多 Server 组合是生产部署的常态，合并多个 Server 的 Tool 列表是 Host 侧的核心职责之一。
