第 6 章：Prompts（提示模板）——用户触发的预设工作流

6.1 Prompt 的语义

Prompt 是三大原语中控制方最明确的一种：它由用户显式触发。在 Host 界面上，Prompt 通常表现为斜杠命令、菜单项或快捷按钮。用户选中后，Host 把 Prompt 生成的消息填入对话框，因此用户获得一个预设好的、参数化的提示模板。

Prompt 解决的问题是：把常用的、结构化的提示词固化下来，供用户一键复用，而不必每次手动书写冗长的提示。

Client 通过两个方法使用 Prompt：

  • prompts/list：列出所有可用 Prompt 及其参数定义。
  • prompts/get：传入参数，获取渲染后的消息列表。

6.2 定义一个 Prompt

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("prompt-server")


@mcp.prompt()
def code_review(language: str, code: str) -> str:
    """生成一个代码审查提示。"""
    return f"""请审查下面这段 {language} 代码，重点关注：
1. 潜在的 bug 与边界条件
2. 性能问题
3. 命名与可读性
4. 安全隐患

代码如下：
```{language}
{code}
```

请按上述四个维度分别给出具体意见。"""

Client 调用 prompts/get 时的报文：

// 请求
{ "jsonrpc": "2.0", "id": 3, "method": "prompts/get",
  "params": {
    "name": "code_review",
    "arguments": { "language": "python", "code": "def f(x): return x/0" }
  } }

// 响应
{ "jsonrpc": "2.0", "id": 3, "result": {
    "description": "生成一个代码审查提示。",
    "messages": [{
      "role": "user",
      "content": { "type": "text", "text": "请审查下面这段 python 代码..." }
    }]
} }

6.3 多消息与角色

Prompt 可以返回多条消息，模拟一段预设的对话历史。这对于需要 few-shot 示例或设定系统角色的场景很有用。

from mcp.server.fastmcp.prompts import base


@mcp.prompt()
def debug_session(error_message: str) -> list[base.Message]:
    """构造一个调试会话的初始对话。"""
    return [
        base.AssistantMessage(
            "我是调试助手。请把你遇到的错误信息告诉我，我会帮你逐步定位。"
        ),
        base.UserMessage(f"我遇到了这个错误：\n\n{error_message}"),
        base.AssistantMessage(
            "收到。为了定位问题，请先确认：这个错误是在什么操作后出现的？"
        ),
    ]

返回的消息列表带有各自的 role：

{ "messages": [
    { "role": "assistant", "content": { "type": "text", "text": "我是调试助手..." } },
    { "role": "user", "content": { "type": "text", "text": "我遇到了这个错误：..." } },
    { "role": "assistant", "content": { "type": "text", "text": "收到。为了定位..." } }
] }

6.4 在 Prompt 中嵌入资源

Prompt 的消息内容不限于文本，还可以嵌入 Resource。因此，用户触发 Prompt 时，相关的资源内容会一并注入上下文。

from mcp.server.fastmcp.prompts import base
from mcp.types import EmbeddedResource, TextResourceContents


@mcp.prompt()
def analyze_log(date: str) -> list[base.Message]:
    """让模型分析指定日期的日志文件。"""
    # 读取日志内容（此处简化）
    log_content = open(f"/var/log/app/{date}.log").read()

    return [
        base.UserMessage("请分析下面这份日志，找出所有 ERROR 级别的异常并归类："),
        base.UserMessage(
            content=EmbeddedResource(
                type="resource",
                resource=TextResourceContents(
                    uri=f"logs://{date}",
                    mimeType="text/plain",
                    text=log_content,
                ),
            )
        ),
    ]

6.5 组合三大原语的工作流

三大原语并非孤立使用。一个成熟的 MCP Server 通常把它们组合成完整工作流。以「生成周报」为例：

  1. 用户触发 Prompt：用户选择「生成周报」这个 Prompt，传入周次参数。
  2. Prompt 嵌入 Resource：Prompt 内部读取本周的提交记录、任务列表等 Resource，注入上下文。
  3. 模型调用 Tool：模型分析数据后，调用 save_report Tool 把生成的周报写入系统。
# 三大原语协作的完整示例
@mcp.resource("commits://{week}")
def get_commits(week: str) -> str:
    """返回指定周的 Git 提交记录。"""
    return run_git_log(week)  # 省略实现


@mcp.tool()
def save_report(week: str, content: str) -> str:
    """把生成的周报保存到系统。"""
    save_to_db(week, content)  # 省略实现
    return f"第 {week} 周周报已保存。"


@mcp.prompt()
def weekly_report(week: str) -> str:
    """生成周报的提示模板。"""
    commits = get_commits(week)
    return f"""基于以下本周提交记录，生成一份结构化周报，
包含"完成事项、进行中、下周计划"三个部分。
生成后请调用 save_report 工具保存。

提交记录：
{commits}"""

在这个工作流中，Prompt 提供入口和上下文，Resource 提供数据，Tool 完成动作。因此，三者共同构成了一个由用户一键触发的完整自动化流程。
