第 1 章

安装与第一次会话

目标是 15 分钟内完成三件事：装好 CLI、让它在陌生仓库里讲清楚项目结构、改掉第一行代码。

场景

你刚接管一个别人的仓库，下午要修一个 bug。README 只写了三行，目录很深，构建命令不确定。先让 Claude 把项目讲清楚，再动手。

1.1 安装

官方推荐原生安装脚本，装完自动更新。macOS、Linux、WSL 用同一条命令：

bash
curl -fsSL https://claude.ai/install.sh | bash

其他安装方式：

平台命令更新方式
macOS（Homebrew）brew install --cask claude-codebrew upgrade claude-code
Windows（PowerShell）irm https://claude.ai/install.ps1 | iex自动
Windows（WinGet）winget install Anthropic.ClaudeCodewinget upgrade Anthropic.ClaudeCode

确认安装：

bash
claude --version
claude doctor

--version 打印版本号；doctor 检查安装路径、设置文件、登录状态。装完提示 command not found，通常是 ~/.local/bin 不在 PATH，重新开一个终端再看。

1.2 登录

进入项目目录，直接启动：

bash
cd /path/to/repo
claude

首次运行会要求登录。支持 Claude 订阅（Pro / Max / Team / Enterprise）、Claude Console（API 计费）以及 Bedrock、Vertex 等云厂商。按提示在浏览器完成授权即可。

已经设置 ANTHROPIC_API_KEY 的环境，会询问是否使用这个 Key。想换账号，在会话里输入 /login。

第一次启动会问「是否信任这个目录」

这是工作区信任机制：不同意为当前项目加载 .claude/ 下的配置、Hooks 和 MCP 服务。只在你确认来源可靠的仓库里同意。不同意也能对话，但项目级配置不生效。

1.3 先问，不改

启动后先做三件事，不要急着让它改代码：

Claude Code 会话
> 这个项目是做什么的？入口文件在哪？
> 构建、测试、启动分别用什么命令？
> 列出目录结构，标出核心模块和它们的关系

再追加一个更具体的问题，用来验证它真的读了代码，而不是猜：

Claude Code 会话
> 用户登录的请求从哪个路由进来，经过哪些文件，最后写哪张表？给出文件路径和行号
为什么先问

这一步同时完成两件事：你确认它理解了项目；它把相关文件读进上下文，后续修改的准确率更高。回答里如果没有具体文件路径，说明它没读到位，换一种问法或直接 @文件 指定。

1.4 第一次修改

从最小改动开始，例如修一个明显的文案或日志问题：

Claude Code 会话
> 把 src/auth/login.ts 里登录失败的提示改成中文，只改这一处，不要动其他逻辑

Claude 会先读文件，再发起编辑。终端会显示 diff 并请求确认：

  • Yes：本次允许；
  • Yes, allow all edits during this session：本次会话内不再询问编辑；
  • No：拒绝，让它换方案。

改完自己看一遍：

bash
git diff

1.5 不进入交互模式也能用

适合脚本和快速检查：

bash
claude -p "用三句话说明这个项目的架构" --output-format json | jq -r '.result'

这条命令执行完就退出，不进入会话。第 7 章会展开。

1.6 这一步的验收

  • claude --version 能打印版本号
  • 能在项目根目录启动会话，并看到当前模型与工作目录
  • 三个问题都得到了带文件路径的回答
  • git diff 里只有你要求改的那一处

1.7 常见问题

现象处理
command not found: claude把安装目录加入 PATH，或重新打开终端；claude doctor 会指出路径问题
一直停在登录页在会话里执行 /login；检查浏览器是否能打开授权页
回答很泛，没有文件路径明确要求「给出文件路径和行号」，或用 @src/xxx.ts 指定文件
每次编辑都要确认选择「allow all edits during this session」，或在第 8 章配置权限规则
