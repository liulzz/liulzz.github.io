第 2 章

让 Claude 懂你的项目

每次新会话都要重复「用 pnpm、测试命令是这个、不要改 generated 目录」，说明项目上下文还没写下来。

场景

第三天，你开了一个新会话，Claude 又用了错误的包管理器，还试图修改自动生成的代码。你需要的不是再解释一遍，而是一份会随仓库走的说明文件。

2.1 先生成，再修改

在项目根目录启动会话，执行：

Claude Code 会话
> /init

/init 会扫描仓库，生成一份 CLAUDE.md，通常包含构建命令、测试方式、目录说明和它能推断出的约定。已经存在 CLAUDE.md 时，它提出改进建议，不会直接覆盖。

生成后不要直接提交，先删掉三类内容：它猜错的、重复的、以及只对一次任务有效的。

2.2 一份能用的 CLAUDE.md

目标是 200 行以内，每条都能被验证。示例：

CLAUDE.md
# 项目说明

B2B 订单系统。前端 React，后端 Fastify，数据库 PostgreSQL。

## 构建与测试

- 安装依赖：`pnpm install`
- 本地开发：`pnpm dev`
- 单元测试：`pnpm test -- --run`
- 类型检查：`pnpm typecheck`
- 提交前必须通过：`pnpm lint && pnpm test -- --run`

## 目录

- `apps/web`：管理后台
- `apps/api`：HTTP 接口
- `packages/domain`：订单与优惠券领域逻辑
- `packages/db`：数据库访问层
- `generated/`：自动生成，禁止手改

## 约定

- TypeScript 严格模式，不用 `any`
- 金额统一用整数分表示，禁止浮点运算
- 新增接口必须同步更新 `openapi.yaml`
- 组件里不直接发请求，统一走 `packages/api-client`

## 禁止

- 不提交 `.env`、密钥、真实用户数据
- 不修改 `generated/` 与数据库迁移历史
- 不为了通过测试而删除或跳过测试

写法上注意两点：

  • 写「执行 pnpm test -- --run」，不要写「记得测试」；
  • 写「金额用整数分」，不要写「注意精度」。

Claude 把 CLAUDE.md 当作上下文而不是强制配置。要真正阻止某个动作，用第 6 章的 PreToolUse Hook，或第 8 章的权限拒绝规则。

2.3 放在哪一层

范围位置适合写什么
组织策略系统目录下的 CLAUDE.md（由 IT 部署）安全规范、合规要求
个人全局~/.claude/CLAUDE.md你个人的偏好：提交信息风格、常用命令
项目共享./CLAUDE.md 或 ./.claude/CLAUDE.md团队共享的构建、规范、目录说明
本地私有./CLAUDE.local.md你自己的测试账号、沙箱地址；加入 .gitignore

加载顺序从宽到窄。项目文件里不要写个人偏好，个人文件里不要写只有这个仓库才成立的规则。

2.4 文件太长就拆开

两种拆法，按用途选：

  • 导入：在 CLAUDE.md 里写 @docs/architecture.md，内容会一起进入上下文。适合架构说明、接口约定。最多四层嵌套。
  • 路径规则：把规则放到 .claude/rules/，用 paths 限定生效范围，只在处理匹配文件时加载。
.claude/rules/api.md
---
paths:
  - "apps/api/**/*.ts"
---

# API 规则

- 所有入参必须用 zod 校验
- 错误响应统一为 `{ code, message, requestId }`
- 新增或修改接口必须更新 `openapi.yaml`

拆分的判断标准：这条规则是否只对一个目录成立。是，就放路径规则；对整个项目都成立，才留在 CLAUDE.md。

2.5 验证它真的加载了

Claude Code 会话
> /context all

在输出里找到 Memory files，确认 CLAUDE.md 和规则文件都在列表里。再看 token 占用：如果项目说明占了很大一块，说明写得太长，该拆了。

另一个验证方式：新开一个会话，直接问「提交前要执行哪些命令」。回答正确，说明上下文生效。

2.6 自动记忆

除了你写的 CLAUDE.md，Claude 还会自己记笔记（auto memory）：当你纠正它、或它发现稳定的项目模式时，会写入按仓库隔离的记忆文件，下次会话自动加载前 200 行或 25KB。它适合记「你纠正过的偏好」，不适合替代团队规范。

觉得它记错了，直接在会话里说「忘掉关于 X 的记忆」，或者查看 ~/.claude/ 下的记忆文件。

2.7 验收

  • 项目根目录有 CLAUDE.md，且不超过 200 行
  • 里面写的是命令和可验证的规则，不是空泛要求
  • /context all 的 Memory files 里能看到它
  • 新会话能正确回答构建与测试命令

2.8 常见坑

坑后果改法
把 CLAUDE.md 写成百科占上下文，关键规则被淹没压到 200 行内，细节放 rules 或 skills
写「写好一点」这类要求无法执行，也无法验证改成具体命令或具体约束
两条规则互相矛盾Claude 随机选一条定期用 /doctor prompt-audit 检查
把密钥写进 CLAUDE.md随仓库泄露密钥只放环境变量或本地文件
