第 8 章

权限、成本与排错

前七章解决「怎么用」。这一章解决「怎么放心地用」：哪些动作必须拦、钱花在哪、出问题先看什么。

场景

团队准备把 Claude Code 推广到十几个人。你需要一份能提交到仓库的权限配置，一套成本观察方法，以及新同事遇到问题时能自查的顺序。

8.1 权限规则写在设置里

项目级配置放在 .claude/settings.json，随仓库共享：

.claude/settings.json
{
  "permissions": {
    "defaultMode": "acceptEdits",
    "allow": [
      "Read",
      "Bash(pnpm test:*)",
      "Bash(pnpm typecheck)",
      "Bash(git status)",
      "Bash(git diff:*)"
    ],
    "ask": [
      "Bash(git commit:*)",
      "Bash(git push:*)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./secrets/**)",
      "Bash(rm -rf:*)",
      "Bash(git push --force:*)"
    ]
  }
}
规则含义
allow直接执行，不再询问
ask每次执行前询问
deny拒绝，并从 Claude 的工具上下文中移除
Tool匹配该工具的所有调用，例如 Read
Tool(specifier)匹配具体输入，例如 Read(./.env)、WebFetch(domain:example.com)

命令规则使用前缀匹配：Bash(pnpm test:*) 允许所有以 pnpm test 开头的命令。deny 优先级高于 allow，同一条命令同时命中时以拒绝为准。

查看和临时调整用：

Claude Code 会话
> /permissions

8.2 设置文件的优先级

同一个键出现在多个文件时，高优先级覆盖低优先级：

优先级来源谁控制
1（最高）组织托管设置IT / 安全团队
2命令行参数本次启动
3.claude/settings.local.json你个人，不提交
4.claude/settings.json项目团队，提交共享
5（最低）~/.claude/settings.json你个人，所有项目

托管设置的优先级最高，个人文件改不动它。用 /status 可以看到当前生效的设置来源。

8.3 成本：先看，再控

交互会话里：

Claude Code 会话
> /usage

/usage 显示当前会话的 token 使用；订阅用户还能看到计划用量条和剩余额度。API 计费用户关注的会话成本也可以在状态栏或 /cost 里查看。

无头运行加硬上限：

bash
claude -p "重构这个模块" --max-budget-usd 2.00 --max-turns 15

预算是客户端估算，可能略有偏差，但足以防止失控。任务越大，越应该拆成多个有上限的小调用。

成本通常花在哪

  • 反复读大文件：一次读取几千行，几轮就占满上下文；
  • 把整仓库或整个日志贴进提示；
  • 一个会话处理多个不相关任务，历史越拖越长；
  • 审查类任务没有限制输出条数，模型不断展开。

对应的做法：用 @文件 精确指定、只传 diff、一个任务一个会话、在提示里写「最多 10 条」。

8.4 上下文管理

命令作用什么时候用
/context查看系统提示、工具、CLAUDE.md、对话各占多少回答变慢或开始忘事
/compact压缩历史，保留摘要同一任务还要继续，但上下文快满
/clear开新会话，旧会话仍可恢复换任务
/rewind回到某一轮之前改错方向

8.5 出问题先查这四步

  1. claude doctor

    在终端执行，检查安装路径、设置文件语法、登录状态。它不启动会话，适合先排除环境问题。

  2. /status 与 /context

    会话内确认当前模型、目录、设置来源，以及 CLAUDE.md 和技能是否真的加载。

  3. --debug

    怀疑 Hook、MCP 或启动流程时，用 claude --debug 启动，或加分类过滤：--debug='mcp,startup'。

  4. 最小复现

    换一个空目录、去掉项目配置再试。能复现就是 Claude Code 本身；不能复现就是项目配置或 Hook 的问题。

8.6 常见症状对照

症状先检查处理
CLAUDE.md 不生效/context all 的 Memory files确认路径与文件名；重启会话
技能找不到/skills，目录是否为 .claude/skills/<name>/SKILL.md修正路径；避免与内置命令重名
Hook 不触发claude doctor 的设置语法；/hooks修正 JSON；确认 matcher 与工具名匹配
MCP 工具不出现claude mcp list、/mcp检查传输类型、令牌、服务是否启动
回答开始丢细节/context/compact 或换新会话
运行被权限阻断/permissions添加 allow 规则，或临时切换权限模式

8.8 团队实施清单

  • 仓库里有 CLAUDE.md，写了构建、测试、目录与禁止事项
  • .claude/settings.json 提交了 allow / ask / deny 规则
  • 至少一个 PreToolUse Hook 保护密钥文件
  • 重复流程已经固化成技能，而不是靠口头约定
  • CI 里的调用有 --max-turns 和 --max-budget-usd
  • 新同事按第 1–3 章能独立完成一次可验证的改动
最后一条建议

把 Claude Code 当成一个需要明确边界的新同事：给它项目说明、给它工具、给它验收标准，也给它明确的禁止项。边界越清楚，审查成本越低。
