第 4 章

会话、分支与回滚

一个任务很少在一次会话里结束。这一章解决三件事：接着昨天的活、在不破坏原方案的前提下试新路、改坏了退回去。

场景

昨天的 bug 修到一半下班了。今天要接着做；同时你想试另一种实现方案，但不希望弄乱已经调通的那条路。

4.1 接着上一次

在同一个项目目录下：

bash
claude -c

-c 会加载当前目录最近的一次会话，包括消息历史和之前的状态。它不会把 claude -p 创建的会话算进来。

如果同时有几个任务，给会话起名字，恢复时更明确：

bash
claude --name coupon-fix
# 下次直接恢复
claude --resume coupon-fix

会话中改名用 /rename coupon-fix-v2。不带名字执行 claude --resume 会打开会话选择器，方向键选择，适合记不住名字的时候。

4.2 开一条分支试另一种方案

分支会复制当前对话，然后把你切到副本里。原来的会话不变。会话内执行：

Claude Code 会话
> /branch try-streaming

从命令行恢复时开分支：

bash
claude --continue --fork-session

区别要记住：/branch 在同一个进程内复制，之前的「本次会话允许」权限继续有效；--fork-session 起的是新进程，权限需要重新批准。两条分支共享同一份工作区文件，所以不要同时让它们改同一批文件。

分支不是 Git 分支

会话分支只隔离对话，不隔离代码。要同时试两种实现，仍然应该配合 Git 工作树或至少 git stash。

4.3 改坏了：回滚

Claude Code 在你每发起一轮对话时自动记录检查点，保留最近 100 个。回滚方式：

Claude Code 会话
> /rewind

输入框为空时连按两次 Esc 也能打开。菜单里可以只恢复对话、只恢复代码，或两者都恢复。

操作恢复内容注意
Restore conversation对话历史回到那一轮之前不回滚文件
Restore code恢复 Claude 编辑过的文件只覆盖 Claude 通过编辑工具改的文件
Restore conversation and code两者都回滚最常用

只用 Bash 命令修改的文件不在检查点里，例如 sed -i、代码生成器输出。这类改动只能靠 Git 恢复。

4.4 上下文快满了怎么办

先看占用：

Claude Code 会话
> /context

能看到系统提示、工具定义、CLAUDE.md、对话各占多少。三种处理方式：

  • /compact：压缩对话，保留摘要。可以加 here 5 保留最近 5 轮原文；
  • /clear：直接开一个空上下文的新会话，旧会话仍可用 /resume 找回；
  • 换任务就换会话。不要让一个会话同时处理三个不相关的问题。
Claude Code 会话
> /compact here 5

4.5 验收

  • claude -c 能恢复昨天的上下文，且知道当前分支
  • claude --resume <name> 能直接进入指定会话
  • /rewind 能把代码和对话退回到指定轮次
  • /context 里各项占用清楚，知道该压缩还是该换会话

坑后果改法
