第 7 章

无头模式与 CI

交互模式适合探索，脚本和流水线需要另一种形态：一次调用、明确输出、可设上限、执行完退出。

场景

每次提 PR，你都想先执行一遍自动审查：找出真实缺陷、输出固定格式、在 CI 里作为检查项。同时不能让一次失控的运行烧掉整月预算。

7.1 一次调用就完成

bash
claude -p "用三句话说明这个项目的架构"

-p（--print）表示非交互：读取提示、执行、把结果写到标准输出、退出。它不会打开会话界面。

管道输入同样可用：

bash
cat build-error.txt | claude -p "用一句话说明根因，再给修复命令"
bash
git diff origin/main...HEAD | claude -p "审查这个 diff，只报告逻辑错误和安全问题"

7.2 让输出可被程序读取

默认输出纯文本。需要脚本处理时换成 JSON：

bash
claude -p "总结这个项目" --output-format json | jq -r '.result'
格式内容用途
text纯文本结果人工阅读、写入文件
json结果、session ID、耗时、成本等脚本解析
stream-json逐行 JSON 事件实时进度、对接其他工具

固定字段：用 JSON Schema 约束

bash
claude -p "从 auth.py 提取主要函数名" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}' \
  | jq '.structured_output'

结果在 structured_output 字段。运行没有产出合法结构时，这个字段可能不存在，脚本要先判断再取值。

7.3 控制权限与成本

无头运行没人点「允许」，必须提前声明哪些工具可以直接用：

bash
claude -p "运行测试并修复失败" \
  --allowedTools "Bash,Read,Edit" \
  --max-turns 20 \
  --max-budget-usd 3.00

三个上限各自管一件事：--allowedTools 管能做什么，--max-turns 管最多几轮，--max-budget-usd 管最多花多少（客户端估算，不等于最终账单）。

完全无人值守的任务再加两个参数：

bash
claude -p "更新依赖版本并运行测试" \
  --permission-mode auto \
  --permission-prompts none \
  --max-budget-usd 5.00

--permission-prompts none 让需要人工确认的请求直接拒绝，避免流水线卡住等一个永远不会来的回答。

不要用 bypassPermissions 执行不可信代码

CI 里更稳的做法是 auto 或 dontAsk 加白名单。容器里运行、限制网络、挂载只读凭据，比放宽权限更有效。

7.4 启动更快：--bare

脚本化调用不需要加载项目的 Hooks、技能、MCP 和 CLAUDE.md 时：

bash
claude --bare -p "把这个 JSON 转成 CSV"

减少启动时的自动发现，代价是它不再了解项目约定。适合纯文本处理，不适合代码修改。

7.5 一个可用的 CI 步骤

.github/workflows/ai-review.yml
name: AI review
on:
  pull_request:

jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Install Claude Code
        run: curl -fsSL https://claude.ai/install.sh | bash

      - name: Review diff
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          git diff origin/${{ github.base_ref }}...HEAD > /tmp/pr.diff
          claude -p "审查 /tmp/pr.diff。只报告逻辑错误、安全问题、缺失测试。
          每条给出文件、行号、原因、建议。没有发现就输出 NO_FINDINGS。
          输出 JSON，字段 findings 为数组。" \
            --allowedTools "Read" \
            --max-turns 10 \
            --max-budget-usd 2.00 \
            --json-schema '{"type":"object","properties":{"findings":{"type":"array","items":{"type":"object"}}},"required":["findings"]}' \
            --output-format json > /tmp/review.json

      - name: Fail on findings
        run: |
          jq -e '.structured_output.findings | length == 0' /tmp/review.json

这段流程的关键不是 YAML，而是三件事：diff 只包含本次改动、工具权限只给只读、预算有上限。审查结果是否阻塞合并，由你决定。

7.6 验证

  • claude -p "..." --output-format json | jq -r .result 能取到文本
  • 带 --max-budget-usd 的任务超限后会停止
  • CI 步骤在无交互环境下能跑完，不等待输入
  • 失败时退出码非 0，流水线能正确标记

7.7 常见坑

坑后果改法
无头运行没有声明 allowedTools需要确认的调用被拒绝，任务半途而废明确白名单，或用 dontAsk 接受拒绝语义
把整仓库塞进提示超上下文，成本失控只传 diff 或相关文件
依赖 structured_output 一定存在脚本报空指针先判断字段是否存在，再解析
在 CI 里用主账号长期令牌泄露后影响面大用专用密钥或 claude setup-token 生成 CI 令牌
以为 -p 会话能在 -c 里恢复找不到会话-p 会话默认不进选择器，用 session ID 显式恢复
