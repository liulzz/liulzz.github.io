00AgentScope Java 2.0 是什么

阿里开源的生产级 Java Agent 框架，Maven 坐标 io.agentscope:agentscope-harness，已在阿里 13+ 业务单元生产运行。2.0 的核心是Harness 工程层——在 ReActAgent 推理内核之上，注入 Workspace / 记忆 / 会话 / 沙箱 / 技能 / 子代理等企业级能力java.agentscope.io +1。

2.0 六大核心能力

  • Event System：31 类类型化事件流，支撑实时 UI 与 HITLjava.agentscope.io。
  • Permission System：工具调用三态闸门 ALLOW / ASK / DENY。
  • Middleware：AOP 风格五阶段钩子（onAgent / onReasoning / onActing / onModelCall / onSystemPrompt）。
  • Workspace & Sandbox：本地 / Docker / K8s / E2B / AgentRun 云沙箱隔离。
  • Multi-Agent Orchestration：agent_spawn / agent_send + 实时事件转发。
  • Distributed Deployment：Redis / MySQL / PostgreSQL / OSS 分布式会话与记忆。

双层架构

┌────────────────────────────────────────────────────────┐
│ HarnessAgent（推荐入口）                                │
│  = ReActAgent + Workspace + 记忆 + 会话 + 沙箱 + 技能    │
│    + Subagent + 上下文压缩 + Plan Mode                  │
├────────────────────────────────────────────────────────┤
│ ReActAgent（无状态推理-行动循环内核）                     │
│  ├── Model      (DashScope/OpenAI/Anthropic/Gemini…)   │
│  ├── Toolkit    (@Tool / MCP / ToolGroup / Skill)      │
│  ├── Permission (ALLOW/ASK/DENY)                       │
│  ├── Middleware (五阶段钩子)                            │
│  └── AgentState (上下文+摘要+权限规则，可持久化)         │
└────────────────────────────────────────────────────────┘

02核心概念

① Message / ContentBlock

最基本数据结构，内容由 TextBlock / ThinkingBlock / ToolUseBlock / ToolResultBlock / ImageBlock 等块列表承载，构造时做严格角色校验。

② Model

统一 ChatModelBase 抽象，官方扩展模块覆盖 Qwen/OpenAI/Anthropic/Gemini/DeepSeek/GLM/Kimi/MiniMax/Ollama；支持最大重试 + Fallback 模型。多 Agent 场景用 DashScopeMultiAgentFormatter。

③ Toolkit

注册工具 / MCP / 技能，反射生成 JSON Schema。方法标 @Tool+@ToolParam 后 toolkit.registerTool(new XxxTools())。

④ Agent（ReActAgent / HarnessAgent）

三个核心方法：call(List<Msg>, ctx) → Mono<Msg>；streamEvents(List<Msg>, ctx) → Flux<AgentEvent>；observe(Msg) 只放上下文不触发推理。

⑤ Event

31 类事件流：TEXT_BLOCK_DELTA / TOOL_CALL_START / RequireUserConfirmEvent / SubagentExposedEvent 等。

⑥ RuntimeContext 与 AgentState

RuntimeContext 单次调用元数据包；AgentState 跨调用持久状态，由 AgentStateStore 按 (userId, sessionId) 加载/保存。

输入 ─► 追加上下文 ─► [ReAct 循环]
                      Reasoning: LLM → 文本 或 工具调用
                      Acting:    Toolkit 派发 → 权限 → 执行 → 回填
                    ─► 返回最终 Msg 或 事件流

03实战 1 · 第一个 Agent：智能问答助手

小场景 1

用 HarnessAgent 构建 "Friday"，同一 sessionId 下多轮对话自动记住上下文。

import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.message.UserMessage;
import io.agentscope.harness.agent.HarnessAgent;
import java.nio.file.Paths;

public class FirstAgent {
    public static void main(String[] args) {
        HarnessAgent agent = HarnessAgent.builder()
                .name("Friday")
                .sysPrompt("你是智能助手 Friday，回答要简洁友好，用中文。")
                .model("dashscope:qwen-plus")   // 自动读 DASHSCOPE_API_KEY
                .workspace(Paths.get(".agentscope/workspace"))
                .build();

        RuntimeContext ctx = RuntimeContext.builder()
                .sessionId("demo").userId("alice").build();

        agent.call(new UserMessage("我叫 Alice，在准备 ReAct 技术分享。"), ctx).block();
        String answer = agent.call(
                new UserMessage("我叫什么名字？在做什么？"), ctx
        ).block().getTextContent();
        System.out.println("Friday> " + answer);
        // → 你叫 Alice，在准备 ReAct 技术分享。
    }
}

04实战 2 · 工具调用：天气查询 Agent

小场景 2

通过 @Tool 注解让 Agent 查"实时"天气（Map 模拟）。

import io.agentscope.core.ReActAgent;
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.message.UserMessage;
import io.agentscope.core.tool.*;
import java.util.Map;

public class WeatherAgent {
    public static class WeatherTools {
        private static final Map<String,String> DB = Map.of(
                "杭州|今天","晴，26°C，东南风 3 级",
                "北京|今天","晴，18°C，空气质量优");
        @Tool(description = "查询指定城市在指定日期的天气。")
        public String getWeather(
                @ToolParam(name="city", description="中文城市名") String city,
                @ToolParam(name="date", description="今天/明天，默认今天") String date) {
            return DB.getOrDefault(city+"|"+date, "暂无数据");
        }
    }
    public static void main(String[] args) {
        Toolkit toolkit = new Toolkit();
        toolkit.registerTool(new WeatherTools());
        ReActAgent agent = ReActAgent.builder()
                .name("WeatherAgent")
                .sysPrompt("天气问题必须调用 get_weather。")
                .model("dashscope:qwen-plus").toolkit(toolkit).build();
        RuntimeContext ctx = RuntimeContext.builder()
                .sessionId("w1").userId("alice").build();
        System.out.println(agent.call(
                new UserMessage("今天杭州和北京哪个适合跑步？"), ctx
        ).block().getTextContent());
    }
}
⚠️ @ToolParam.name 必须显式指定（Java 默认不保留参数名），否则注册失败。

06实战 4 · 多 Agent MsgHub 辩论赛

小场景 4

正方/反方/主持人三方辩论，MsgHub 广播 + 结构化输出判分。

import io.agentscope.core.ReActAgent;
import io.agentscope.core.memory.InMemoryMemory;
import io.agentscope.core.message.*;
import io.agentscope.core.pipeline.MsgHub;
import io.agentscope.extensions.model.dashscope.*;
import io.agentscope.extensions.model.dashscope.formatter.*;

public class DebateExample {
    public static class JudgeResult {
        public boolean finished; public String correctAnswer;
    }
    public static void main(String[] args) {
        DashScopeChatModel model = DashScopeChatModel.builder()
                .apiKey(System.getenv("DASHSCOPE_API_KEY")).modelName("qwen-plus")
                .formatter(new DashScopeMultiAgentFormatter()).build();

        ReActAgent pro = ReActAgent.builder().name("正方")
                .sysPrompt("支持远程办公，每次一个论点不超过 60 字。")
                .model(model).memory(new InMemoryMemory()).build();
        ReActAgent con = ReActAgent.builder().name("反方")
                .sysPrompt("反对远程办公，每次一个论点不超过 60 字。")
                .model(model).memory(new InMemoryMemory()).build();
        ReActAgent mod = ReActAgent.builder().name("主持人")
                .sysPrompt("判定辩论是否可以得出结论。")
                .model(model).memory(new InMemoryMemory()).build();

        for (int round=1; round<=3; round++) {
            try (MsgHub hub = MsgHub.builder().participants(pro, con).build()) {
                hub.enter().block();
                Msg m1 = pro.call(new UserMessage("请亮出观点。")).block();
                System.out.println("【正方】" + m1.getTextContent());
                Msg m2 = con.call(new UserMessage("请反驳。")).block();
                System.out.println("【反方】" + m2.getTextContent());
            }
            Msg judge = mod.call(new UserMessage("能否得出结论？"), JudgeResult.class).block();
            JudgeResult r = judge.getStructuredData(JudgeResult.class);
            if (r.finished) { System.out.println("结论：" + r.correctAnswer); return; }
        }
    }
}
💡 多 Agent 必须用 MultiAgentFormatter + 各自独立 InMemoryMemory，否则历史串扰。

07实战 5 · HITL 与权限系统

小场景 5

敏感工具执行前暂停，用户批准后继续 / 拒绝则回传"已取消"。

import io.agentscope.core.ReActAgent;
import io.agentscope.core.hook.Hook;
import io.agentscope.core.hook.event.PostReasoningEvent;
import io.agentscope.core.message.*;
import io.agentscope.core.tool.*;
import reactor.core.publisher.Mono;
import java.util.List; import java.util.Scanner;

public class SensitiveOpAgent {
    public static class MailTools {
        @Tool(description="发送邮件")
        public String sendEmail(
                @ToolParam(name="to", description="收件人") String to,
                @ToolParam(name="subject", description="主题") String subject) {
            return "已发送 " + to;
        }
    }
    public static void main(String[] args) {
        Hook confirm = new Hook() {
            @Override public <T> Mono<T> onEvent(T e) {
                if (e instanceof PostReasoningEvent ev) {
                    boolean hit = ev.getReasoningMessage()
                        .getContentBlocks(ToolUseBlock.class).stream()
                        .anyMatch(t -> t.getName().equals("send_email"));
                    if (hit) ev.stopAgent();   // 挂起等审批
                }
                return Mono.just(e);
            }
        };
        Toolkit tk = new Toolkit(); tk.registerTool(new MailTools());
        ReActAgent agent = ReActAgent.builder().name("OpsBot")
                .sysPrompt("运维助手").model("dashscope:qwen-plus")
                .toolkit(tk).hook(confirm).build();

        Msg resp = agent.call(List.of(new UserMessage(
                "给 bob@example.com 发一封主题'周报'的邮件"))).block();
        Scanner in = new Scanner(System.in);
        while (resp.hasContentBlocks(ToolUseBlock.class)) {
            resp.getContentBlocks(ToolUseBlock.class)
                .forEach(t -> System.out.println("待执行：" + t.getName() + " " + t.getInput()));
            System.out.print("批准？[y/N] ");
            boolean ok = in.nextLine().trim().equalsIgnoreCase("y");
            resp = ok ? agent.call().block()
                      : agent.call(List.of(Msg.builder().role(MsgRole.TOOL)
                          .content(resp.getContentBlocks(ToolUseBlock.class).stream()
                              .map(t -> ToolResultBlock.of(t.getId(), t.getName(),
                                  TextBlock.builder().text("用户已取消").build()))
                              .toArray(ToolResultBlock[]::new)).build())).block();
        }
        System.out.println(resp.getTextContent());
    }
}

GenerateReason 三种暂停原因：REASONING_STOP_REQUESTED / ACTING_STOP_REQUESTED / PERMISSION_ASKING。无人值守用 PermissionMode.DONT_ASK（ASK 自动降级为 DENY）。

09结构化输出

让 Agent 输出严格符合 Java POJO 的数据，自然语言 → 类型化对象java.agentscope.io +1。

两条路径，自动降级

  • Native JSON Schema：模型原生支持（DashScope / OpenAI / Gemini 等），单次调用。
  • 合成 Tool-Call：框架自动生成"结构化工具"，模型通过 tool_call 返回。Native 失败自动 fallback，无需干预。
小场景 9

从商品描述中提取结构化信息。

import io.agentscope.core.ReActAgent;
import io.agentscope.core.message.UserMessage;
import java.util.List;

public class ProductInfo {
    public String name;
    public Double price;
    public List<String> features;
    public ProductInfo() {}   // 必须有无参构造
}

ReActAgent agent = ReActAgent.builder().name("extractor")
        .sysPrompt("从文本中提取商品信息。")
        .model("dashscope:qwen-plus").build();

Msg resp = agent.call(
        new UserMessage("Apple Watch S10，售价 ¥2999，支持血氧、ECG、跌倒检测"),
        ProductInfo.class).block();
ProductInfo data = resp.getStructuredData(ProductInfo.class);
System.out.println(data.name + " / " + data.price + " / " + data.features);
// → Apple Watch S10 / 2999.0 / [血氧, ECG, 跌倒检测]

10RAG 知识库

两个核心组件：Reader（读取+分块成 Document）和 Knowledge（存储+向量检索）java.agentscope.io +1。

两种集成模式

模式机制优点缺点
Generic检索结果自动前置到用户消息简单，Agent 无感每次都检索，浪费 token
AgenticAgent 拿到 retrieve_knowledge 工具自主决定何时查灵活，可重写查询依赖模型决策能力
小场景 10

让 Agent 基于公司内部文档回答问题（Agentic 模式）。

import io.agentscope.core.rag.*;
import io.agentscope.core.rag.store.SimpleKnowledge;
import io.agentscope.core.rag.reader.*;
import io.agentscope.core.tool.Toolkit;

// 1. 读取并分块文档
Reader reader = new TextReader(chunkSize=512, splitBy="paragraph");
List<Document> docs = reader.read(Paths.get("./docs/company_handbook.txt"));

// 2. 构建向量知识库并入库（Simple 是本地最小实现）
SimpleKnowledge knowledge = SimpleKnowledge.builder()
        .embeddingModel("dashscope:text-embedding-v3")
        .build();
knowledge.addDocuments(docs);

// 3. Agentic 模式：注册为工具
Toolkit toolkit = new Toolkit();
toolkit.registerKnowledge(knowledge);   // 生成 retrieve_knowledge 工具

// 4. 构建并调用 Agent
ReActAgent agent = ReActAgent.builder()
        .name("FAQBot")
        .sysPrompt("回答公司相关问题前必须先调用 retrieve_knowledge。")
        .model("dashscope:qwen-plus")
        .toolkit(toolkit).build();
agent.call(new UserMessage("我们公司的年假制度是什么？")).block();

Generic 模式只需把 Knowledge 对象传给 Builder：.knowledge(knowledge)。生产环境可替换为百炼知识库 / Milvus / Elasticsearch 等扩展实现。

14Subagent 子代理

让父 Agent 把"独立、上下文重、可并行"的任务委派给子代理，不污染自己的循环。每个子代理是临时 HarnessAgent，有独立会话，结果通过工具结果返回java.agentscope.io。

启用条件

  • 当前 Agent 不是叶子节点
  • 未调用 disableSubagents()
  • 已配置 model

满足后自动注册 SubagentsHook，暴露 6 个工具：agent_spawn / agent_send / agent_list / task_output / task_cancel / task_list。

三种声明方式（三选一）

# 方式 1：workspace/subagents/reviewer.md
---
name: reviewer            # 可省略，文件名即 agent_id
description: 代码审查专家，当需要审查代码质量时调用。
persist_session: false
expose_to_user: false
---
你是代码审查专家。对传入代码输出问题清单和改进建议。

// 方式 2：程序化 inline
// 方式 3：URL 远程加载
小场景 13

父 Agent 把"代码审查"委派给子代理，同步等待结果；同时启动一个后台任务异步分析日志。

HarnessAgent parent = HarnessAgent.builder()
        .name("orchestrator").model("dashscope:qwen-plus")
        .workspace(Paths.get(".agentscope/workspace"))   // 含 subagents/reviewer.md
        .build();

// 模型会自主调用：
//   agent_spawn(agent_id="reviewer", prompt="审查 XXX", timeout_seconds=60)
//   agent_spawn(agent_id="log-analyst", prompt="分析近 7 天日志", timeout_seconds=0)
//   → 返回 task_id，后台跑
//   后台任务结束前自动注入 <system-reminder> 到父 Agent 上下文

同步 vs 后台

参数行为
timeout_seconds > 0（默认 30，最大 600）同步等待，超时自动升级为后台任务（status: timeout_promoted）
timeout_seconds = 0立即返回 task_id，后台运行
persistSession(true)同一 (parentSessionId, agentId, label) 复用实例，保留会话
expose_to_user(true)通过 Channel 直接暴露给用户，发 SubagentExposedEvent

强制同步 / 暴露给用户

RuntimeContext ctx = RuntimeContext.builder()
        .sessionId("s1").userId("alice")
        .put(AgentSpawnTool.CTX_FORCE_SYNC, true)
        .put(AgentSpawnTool.CTX_FORCE_SYNC_TIMEOUT_SECONDS, 120)
        .put(AgentSpawnTool.CTX_EXPOSE_TO_USER, true)
        .build();
💡 后台任务结果自动 push back——在父 Agent 下一次推理前，框架把已完成任务结果作为 <system-reminder> 注入，无需写"记得调 task_output"这样的提示。

16Channel / Gateway 多渠道接入

Gateway 处理会话管理、并发控制、多 Agent 路由；Channel 把具体 IM/Web 适配进 Gateway 的路由模型。绝大多数场景无需直接操作——agent.channel(...) 一行接入java.agentscope.io。

小场景 15

把同一个 Agent 接到 Web Chat UI、钉钉机器人、飞书机器人，自动隔离各渠道会话。

HarnessAgent agent = HarnessAgent.builder()
        .name("assistant").sysPrompt("通用助手")
        .model("dashscope:qwen-plus").build();

// 1. Web Chat UI 通道
ChatUiChannel chat = agent.channel(ChatUiChannel.create());

// 2. 发送消息：每 userId 自动独立 session
chat.send(SendOptions.userId("user-1"), "你好！").block();
chat.send(SendOptions.userId("user-1"), "继续上一话题").block();
chat.send(SendOptions.userId("user-2"), "Hi there").block();

// 3. 同一用户多会话
chat.send(SendOptions.of("user-1", "session-a"), "话题 A").block();
chat.send(SendOptions.of("user-1", "session-b"), "话题 B").block();

// 4. 流式 + 多 Agent 路由
chat.sendStream(
        SendOptions.userId("user-1").withAgentId("support"),
        "北京的天气？")
     .doOnNext(e -> {
         if (e instanceof TextBlockDeltaEvent d) System.out.print(d.getDelta());
     }).blockLast();

    emit-run-finished-after-error: false

// 前端发送 RunAgentInput { threadId, runId, messages, tools, state }
// 返回 SSE 流，前端 @ag-ui/client 直接消费

HITL 回传

Agent 因权限 ASK 暂停时，RUN_FINISHED 携带 outcome.interrupts[]。前端展示审批 UI，用户决策后通过 resume[] 字段回传：

{
  "resume": [{
    "interruptId": "...",
    "status": "resolved",
    "payload": { "approved": true, "editedArgs": {...} }
  }]
}

支持 payload.approved（布尔）/ payload.editedArgs（完整替换原参数，框架会重建 ToolUseBlock）。

@RestController
public class ChatController {
    private final ChatUiChannel chat;
    public ChatController(ChatUiChannel chat) { this.chat = chat; }

    @GetMapping(value="/chat", produces=MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> chat(
            @RequestParam String userId, @RequestParam String message) {
        return chat.sendStream(SendOptions.userId(userId), message)
                .map(e -> ServerSentEvent.<String>builder()
                        .event(e.getType().name())
                        .data(toJson(e)).build());
    }
}

20常见问题排查

症状排查思路
UnsupportedClassVersionErrorJDK 必须 17+，用 java -version 确认。
.model("dashscope:...") 解析失败① 引入 agentscope-extensions-model-dashscope；② DASHSCOPE_API_KEY 已 export。
@Tool 不被调用① registerTool 已调用；② @ToolParam.name 显式；③ description 写清楚。
多 Agent 历史串扰各自独立 InMemoryMemory + MultiAgentFormatter。
WebFlux 中 .block() 报错控制器直接返回 Flux<AgentEvent>，不 block。
长对话上下文超限配置 CompactionConfig，或启用 ToolResultEvictionConfig 落盘大结果。
结构化输出字段为 nullPOJO 必须有无参构造；DashScope Thinking 模式下走 fallback 路径。
RAG 每次都检索浪费 token换 Agentic 模式，把 Knowledge 注册为工具。
MCP 工具名冲突工具命名空间 mcp__{server}__{tool} 自动避免；检查 server_name 是否重复。
Plan 模式下工具全被拒绝正常——只读阶段仅允许 plan_* / todo_write；退出需 HITL。
Skill 未被加载检查 SKILL.md frontmatter 是否有 name + description；workspace 路径是否正确。
Subagent 没被调用① 未配 model；② 调用了 disableSubagents()；③ workspace/subagents/*.md 缺失或 description 不清晰。
后台任务结果没回来用 wait_async_results(task_ids=..., wait_all=true) 做屏障等待。
Docker 沙箱启动失败确认 Docker daemon 可用，image 已 pull，端口未被占用。
Channel 消息收不到检查适配器 Token/Secret 配置；钉钉用 Stream 模式需 WebSocket 网络可达。
AG-UI 前端收不到 finish 事件RUN_ERROR 与 RUN_FINISHED 互斥，需兼容旧客户端则设 emit-run-finished-after-error=true。
重启后会话丢失JsonFileStore 仅单机；生产切 RedisAgentStateStore。
